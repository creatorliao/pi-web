# 需求清单：完整历史与系统提示词在文件区展示

| 属性 | 值 |

| 日期 | 2026-08-19 |

## 1. 问题

「完整历史」和「系统」是好能力，但现在用 **顶栏下拉 / 新标签页 HTML** 展示。用户在文件区已经形成「打开一份文档」的预期，下拉破坏这个预期。

## 2. 目标

- 完整历史、系统提示词当作 **Markdown 文档** 出现在右侧文件区（可虚拟、可拼接）。
- 不再为这两项另开下拉或独立展示层。
- 用户预期：点菜单 = 打开一个 `.md` 标签，和打开仓库里的文件一样。

## 3. In Scope

| # | 需求 | 优先级 |
|---|------|--------|
| F-01 | 「完整历史」打开右侧虚拟 `*.md` 标签，内容为当前会话上下文的可读 Markdown | 必做 |
| F-02 | 「系统」打开右侧虚拟 `*.md` 标签，内容为完整系统提示词 | 必做 |
| F-03 | 去掉这两项的下拉面板；完整历史不再 `window.open` HTML | 必做 |
| F-04 | 虚拟文件走现有 FileViewer（预览 / 源码），不进真实磁盘 | 必做 |

## 4. 非目标

- 不重做 HTML export API（仍可留给以后下载）。
- 不把「生成标题 / 分支」改成文件（它们是动作和导航，不是文档）。
- 不把虚拟 md 写进会话目录。
