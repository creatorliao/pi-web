## 1. 复述（确认无偏差）

用户对当前 **聊天区顶栏** 不满意：按钮过多、配置类入口和会话操作混在一起，干扰「现在在干什么」的理解。希望参考 **Cowork** 一类产品：

- 侧栏主操作更直白：「新建」改为 **「新建会话」**。
- 主题、语言等 **应用级配置** 不应占顶栏。
- 左下角用 **一个设置按钮** 打开 **设置页**，把分散的配置收进去。

本轮只做：记需求、给方案、等确认。**未改代码。**

## 2. 目标（Why + What）

- **业务目标**：把「开对话 / 看对话」和「改应用配置」拆开，降低顶栏认知负担。
- **用户价值**：新用户一眼知道左上是开新对话；要改主题、语言、模型、技能、插件时，走固定的左下角设置，而不是在顶栏猜图标。
- **成功标准**：
  - 中文「新建」变为「新建会话」；英文同步为明确的 New session。
  - 桌面顶栏不再出现主题、语言入口。
  - 侧栏左下角有单一「设置」入口，能覆盖现有模型 / 技能 / 插件配置，以及外观（主题、语言）。
  - 会话进行中的操作（看历史、改分支、看系统提示）不再伪装成「设置」。

## 3. 现状调查（产品结构，不是实现清单）

调查范围：`SessionSidebar` 顶区、`AppShell` 顶栏与侧栏底栏、已有三个配置弹层、`zh-CN` 文案。对照用户截图。

### 3.2 桌面聊天顶栏（用户截图右侧）

移动端已把后半段收进「⋯」，桌面仍全部平铺。

### 3.3 侧栏底部（已有配置，但不是「设置页」）

左下已有三个并列按钮：**模型 / 技能 / 插件**，分别打开三个独立大弹层（`ModelsConfig` / `SkillsConfig` / `PluginsConfig`）。空状态文案还写「点击底部的模型按钮」。

问题：配置入口已经在左下，但被拆成三个；主题和语言却在顶栏。用户要找「设置」时，没有一个词对得上。

### 3.4 其他偏好（本轮是否收纳待决）

输入框右侧有 **完成提示音** 开关（`localStorage: pi-sound-enabled`）。它是应用偏好，但位置在作曲区，不是顶栏。

## 4. 参考：Cowork 类信息架构

Cowork / Claude 桌面类产品的稳定模式：

1. **左栏**：会话列表 + 「新对话」主按钮。
2. **左下角**：一个齿轮 / 「Settings」，打开独立设置界面。
3. **设置页**：外观、语言、账号 / 能力扩展分栏，而不是顶栏图标。
4. **对话区顶栏**：只留与 **当前这一场对话** 有关的东西，或几乎留空。

pi-web 应对齐的是第 2、3 条和第 1 条的文案，而不是把「分支 / 系统提示」塞进设置——那些是会话工具，放进设置会让「设置」变成杂物抽屉。

## 6. 非功能需求

- **兼容**：桌面与移动都要能改主题和语言；移动顶栏「⋯」里不再放主题 / 语言（改走设置）。
- **可达性**：设置按钮有可见文字或明确 `aria-label`；设置页可用键盘关闭（与现有弹层一致）。
- **安全**：不扩大文件 / 凭据暴露面；设置页只重组入口。
- **性能**：设置页按分区挂载现有大弹层内容，避免一次挂载三个重型配置树。

## 7. 非目标（Out of Scope）

- 不重做模型 / 技能 / 插件的内部表单与接口。
- 不新做账号体系、云同步设置。
- 不改会话文件格式、不改 Agent 内核。
- 不做顶栏视觉大改版（新品牌色、新图标体系）——只做信息架构收纳。
- 不把「选择项目 / 刷新列表」搬进设置。
- 本轮不立项 `01-Projects/R…` 文件夹（用户未要求 para-structure）。
