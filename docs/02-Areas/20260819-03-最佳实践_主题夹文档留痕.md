# 最佳实践_主题夹文档留痕

| 属性 | 值 |
|------|----|
| 适用 | 本仓 `docs/01-Projects` 专题落盘；协作入口见根目录 `AGENTS.md` |
| 第一要义 | **文档留痕**：用户说过的需求、方案、分析，必须落到主题夹，不能只停在对话里 |

本文回答：人（和智能体）**应该怎么想、怎么做、为什么这样做**。交付物长什么样见 `AGENTS.md` 里 PARA 按维分流表。

---

## 1. 先想清楚：留痕先于改代码

用户一旦给出需求、方案、分析或改善意见，**先落盘再动手**（或与实现同轮落盘，不得「做完再说、回头再补」）。

对话会过期、会话会分叉、别人接不上。主题夹才是可检索、可交接的账本。没有夹内文件，就不算这件事被接住。

不要等用户说「写进 docs」。**主动记录**是默认动作。

---

## 2. 按主题存，不按日期开新夹

需求、方案、分析报告、改善报告、任务说明，全部按**主题**进 `docs/01-Projects/<已有或新建的主题夹>/`。

- 主题 = 用户在反复谈的那一块产品能力或问题（例如「界面 Cursor 化布局」「文件区滚动与提示词分区」）。
- 同一主题的后续轮次（细化需求、第二版方案、补充分析）**追加文件到同一夹**，夹名上的日期是**开题日**，不是「今天又开一夹」。
- **禁止**因为「今天又聊了一次」或「这是新的一轮对话」就 `para-structure cp` 再开平行夹。

判断「是不是同一主题」：

| 视为同一主题（追加） | 视为新主题（才允许新建夹） |
|----------------------|----------------------------|
| 同一界面区域 / 同一能力的继续改、补洞、出第二版方案 | 用户明确换了一块独立能力 |
| 标题同义或是已有夹的子问题（顶栏、历史分组仍属「界面 Cursor 化布局」） | 与已有夹没有稳定从属关系 |
| 用户说「接着上次」「同一专题」「还是那个文件区」 | 用户点名新专题名且现有夹对不上 |

拿不准时：**先列 `docs/01-Projects/` 目录，选最贴的已有夹追加**；只有列完仍对不上，才新建。

正例：`R20260819-03-界面Cursor化布局/` 里从 `01-需求` 一直加到 `08-方案`，都是同一主题。  
反例：同一「文件区滚动」再开 `R20260819-11-文件区滚动…`。

---

## 3. 怎么做（操作顺序）

1. **列夹**：看 `docs/01-Projects/` 下现有 `R*-主题` 名称，用主题语义匹配，不要只比日期。
2. **定夹**：命中则进入该夹；未命中再用 `para-structure cp "主题"`（或手建同名 `R{当日}-xx-主题`）。
3. **编号**：读该夹已有 `NN-` 前缀，取最大号 + 1。类型写进文件名：`需求` / `方案` / `分析报告` / `问题与需求` 等。
4. **写盘**：一篇一事；同轮既有需求又有方案就两份文件，不要揉成只有对话摘要。
5. **回写索引**：有 `00-README.md` 则补一行文档表，方便下一轮接着找。

夹内不要再套主题子目录。

---

## 4. 为什么这样是对的

- **可追溯**：方案能指回需求，分析能指回同一夹，不用翻聊天记录。
- **不碎片化**：主题夹是唯一账本；按日开夹会把同一能力拆成无法对照的平行宇宙。
- **交接成本低**：后来的人只打开一个夹就能看到演进，而不是在 Areas 根或多个 `R日期` 夹里拼图。

---

## 5. 检查清单

- [ ] 本轮用户需求 / 方案 / 分析是否已有对应 `.md`（不是只在回复里）
- [ ] 落点是否为 `01-Projects` 某一主题夹（不是 `02-Areas/…-需求.md`）
- [ ] 落盘前是否已浏览现有主题夹并排除「其实是同一主题」
- [ ] 同主题是否只追加、没有新建平行夹
- [ ] 夹内序号是否接续，`00-README` 是否已更新
