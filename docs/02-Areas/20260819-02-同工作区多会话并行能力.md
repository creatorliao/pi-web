## 1. 结论先说

**内核与产品数据模型已经支持「同一工作目录、多条独立会话同时执行」。** 这与 Cursor「同一个 Workspace 里开多条 Chat / Agent 并行」在**执行层**是同级能力：各会话有自己的上下文文件、自己的 `prompt()` 循环，互不占用「全局只准跑一个 Agent」的锁。

**界面层不等同。** Cursor 常见体验是：同一工作区里多条对话可同时开着（分屏、多页签、或后台 Agent 列表仍可见流式进度）。pi-web **一次只挂载一个 `ChatWindow`**；切走后后台继续跑，靠侧栏「运行中」和完成提醒回来看。因此：

| 对照项 | Cursor（用户期望） | pi-web 现状 |
|--------|-------------------|-------------|
| 同一工作区多条会话 | 有 | **有**（同一 `cwd` 多份 `.jsonl`） |
| 多条同时在跑（各打模型、各跑工具） | 有 | **有**（`__piSessions` 按 id 并存） |
| 切走不中止后台任务 | 有 | **有**（卸载只关本页 SSE，不 `abort`） |
| 屏幕上并排看两条对话往外冒字 | 常见 | **无**（单聊天窗 + `sessionKey` 重挂载） |
| 每条会话独立上下文 | 有 | **有** |
| 每条会话再开一个系统进程 | 视产品（本地/云端 Agent） | **无**（全在同一 Next.js Node 进程） |

**一句话：** 「同等功能」若指**同一目录里同时干活**——已经实现。若指**Cursor 式多对话同屏/多页签同时盯流**——还没有，属于 UI 增量，不是内核缺口。

## 2. Cursor 能力拆开看（避免混谈）

用户说的「同一个工作空间里同时执行多个会话」通常叠了四层：

1. **工作区身份**：多条对话绑定同一棵代码树（同一 `cwd` / 同一 repo）。
2. **上下文隔离**：A 的历史不影响 B 的 token 窗口。
3. **执行并行**：A 还在跑工具时，B 可以立刻再发一条。
4. **观察并行**：人能同时看见（或至少不打断）多路进度。

pi-web 对 1～3 已具备；第 4 层是「单焦点 + 后台指示」，不是「多焦点同时渲染」。

本仓另有专题 [R20260819-06](../01-Projects/R20260819-06-Cursor多会话串行依赖/00-README.md) 讨论的是 Cursor **串行依赖**（A 结束后再开 B），与本报告的**并行**相反，不要混用结论。

## 3. 本仓特性：会话与工作区怎么对应

### 3.1 工作区在本产品里叫什么

界面文案是「项目」，本质是会话的 **`cwd`**（外加 Git 时把主仓与 worktree 归到同一 `projectRoot`）。不是 VS Code / Cursor 的 `.code-workspace` 文件。

同一目录下可以有任意多条会话文件：

```text
~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl
```

「新建」只换会话 id，默认仍用当前选中目录。点另一条会话会带上那条自己的 `cwd`（同项目不同 worktree 时等于换 checkout）。

### 3.2 用户怎么在同一工作区开第二条

1. 侧栏已选中某项目 / 某目录。
2. 在会话 A 发送（可长时间跑）。
3. 再点「新建」，或点已有会话 B。
4. 在 B 再发送。A 不会因切走而停止。

侧栏对 `runningSessionIds` 打运行标记；其他项目有运行/未读时，收起的项目按钮也会有活动计数。后台完成可响铃、未读、浏览器通知。

## 4. 代码依据：为什么能并行

### 4.1 注册表按会话 id，没有全局互斥

`lib/rpc-manager.ts` 用 `globalThis.__piSessions: Map<string, AgentSessionWrapper>` 存包装器。`startRpcSession()` 的锁 `__piStartLocks` **只按 sessionId 合并**，避免同一 id 并发启动两次，**不会**把「别的 id 正在跑」挡掉。

新建会话用一次性 `tempKey = __new__${randomUUID()}`（`app/api/agent/new/route.ts`），避免毫秒内两条新建撞到同一把锁、被合成一条。

`getRunningRpcSessionIds()` 遍历整张 Map，把所有 `isRunning()` 的 id 返回。这是产品按「集合」而不是「最多一个」设计的直接证据。

对外接口：

| API | 含义 |
|-----|------|
| `POST /api/agent/new` | 新 id、新 `AgentSession` |
| `POST /api/agent/[id]` | 只对该 id `prompt` / `abort` |
| `GET /api/agent/running` | 当前所有 running id |
| `GET /api/agent/running/events` | running 集合的 SSE |

侧栏在页签可见时约每 2.5 秒拉 `/api/agent/running`；另有 running SSE 可推送变更。

### 4.2 什么叫「这条还在跑」

包装器 `isRunning()` 为真当：仍存活，且 `pendingPromptCount > 0`，或内核 `isStreaming` / `isCompacting` / `isBashRunning`。

同一 `sessionId` 内部仍是**一轮主循环**（可排队跟进），不能在同一条对话里叠两个互不相关的独立 Agent。并行指的是 **A 与 B 两个 id**。

### 4.3 切走为什么不断掉

`AppShell` 中间只有一个 `ChatWindow`，用 `key={sessionKey}` 换会话即卸载重挂。`useAgentSession` 卸载会关掉本页 `EventSource`，**不向服务端发 `abort`**。包装器留在 Node 进程里继续 `prompt()`。再点回来时，若 `GET /api/agent/[id]` 仍 `isStreaming`，会重连 SSE 接上。

完成音放在 `AppShell` 而不是 `ChatWindow`，就是为了「非当前会话跑完也能响」。

### 4.4 同一 `cwd` 会不会被程序禁止并行

**不会。** `hasBusyRpcSessionForCwd()` 只用于「该目录有会话在跑时，不要改项目信任并拆掉包装器」（`app/api/project-trust`），**不是**「第二会话不准启动」。

工具（bash / 写文件）都在各自会话的 `cwd` 下执行。同一目录双开时，**文件系统没有会话级锁**：两边同时改同一文件会互相覆盖，这是工作区并行的固有风险，Cursor 本地双 Agent 同样存在。

### 4.5 和「再开一个 pi」的区别

并行的是进程内多个 `createAgentSessionFromServices()`，不是 `spawn("pi")`。详见领域笔记 `20260819-01`。多路同时打同一 API Key 会叠加配额与账单；多路编译会抢本机 CPU。程序几乎不设「最多同时 N 路」硬顶。空闲约 10 分钟后包装器可能销毁，会话文件仍在，下次发送会重新加载。

两个浏览器页签连同一 pi-web 时，可以分别盯不同会话，底层仍是同一进程里的多包装器。

## 5. 与 Cursor「同等」差在哪（特性缺口）

下列不是「不能并行」，而是**体验不对齐**：

| 缺口 | 说明 | 严重程度 |
|------|------|----------|
| 单聊天窗 | 不能并排或用多个对话页签同时看两条流 | 体验 P2（能力已有，观察不便） |
| 切走丢本地流式缓冲 | 重挂载后靠重连/调和接上，不是内存里第二套 UI 状态一直活着 | P2 |
| 无「工作区级 Agent 面板」 | Cursor 常有后台任务列表；本仓靠侧栏行内转圈 + 项目活动角标 | P2 |
| 同目录写冲突无协调 | 无文件锁、无「B 等待 A 改完」的产品能力 | 已知限制；串行编排见 R06 |
| 资源无上限 | 用户可同时点很多条，服务端照单全收 | 运维/成本，非功能缺失 |

## 6. 改善选项（文档止，不施工）

若目标是「更像 Cursor 的同工作区并行」，而不是再补一条执行通道：

- **选项 A（推荐，小）**：保持单窗，加强后台可观测——运行中会话固定钉在侧栏顶部、主区轻量进度条、完成跳转。成本低，对齐「同时执行」的操作闭环。
- **选项 B**：同一工作区多对话页签（仍一个可见流，页签保活或切回秒开）。接近 Cursor Chat 页签，不改内核。
- **选项 C**：分屏双 `ChatWindow`。观察并行最像 Cursor，状态/音频/快捷键复杂度高。

## 7. 给使用者的最短说明

**同一目录同时跑两件事（现在就能用）：**

1. 会话 A 发送。  
2. 「新建」或点会话 B，再发送。  
3. 看侧栏运行标记；做完点回去看结果。

**现在做不到的：** 左右（或上下）两个对话框同时看字往外冒；也不必、也无法为每条对话再开一个本机 `pi`。
