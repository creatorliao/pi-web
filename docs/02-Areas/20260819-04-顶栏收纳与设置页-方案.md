## 1. 设计原则

1. **主路径只有一个动词**：左上「新建会话」= 开一场新对话。
2. **设置只有一个门**：左下角「设置」= 改应用和能力，不改「这一场对话讲到哪」。
3. **顶栏只回答「这一场」**：布局开关、当前会话工具、用量。不放主题、语言。
4. **不过度设计**：不重写三个配置弹层，只做壳与入口。
5. **小白能对上号**：图标旁边有字；主题是三选一，不是循环猜。

## 2. 推荐信息架构

```text
┌ 侧栏 ─────────────────┐  ┌ 聊天区 ──────────────────────────┐
│ 标题                    │  │ [侧栏]  …会话工具溢出…  [用量][文件] │
│ [+ 新建会话] [刷新]     │  │                                  │
│ 项目选择                │  │  消息列表                         │
│ 会话列表                │  │                                  │
│                         │  │  输入框（模型/思考/工具仍在此）    │
│ [⚙ 设置]                │  └──────────────────────────────────┘
└─────────────────────────┘
```

设置打开后（桌面居中大面板，沿用现有 Config 弹层尺度）：

```text
┌ 设置 ─────────────────────────────────────┐
│ 外观 │ 模型 │ 技能 │ 插件                  │
│                                           │
│  （当前分栏内容）                          │
└───────────────────────────────────────────┘
```

## 3. 分区设计

### 3.1 侧栏顶部

| 现在 | 之后 |
|------|------|
| 「新建」 | 「新建会话」；`title` 仍说明「在 {path} 中新建会话」 |
| 刷新 | 不动 |

### 3.2 侧栏底部

| 现在 | 之后 |
|------|------|
| 模型、技能、插件三个按钮 | **一个「设置」按钮**，打开设置壳，默认停在「外观」或用户上次分栏（首次默认外观） |

技能 / 插件在未选项目时仍不可用：设置壳里这两个分栏 disabled，并说明「先选择项目」。不要让整个设置按钮 disabled，否则主题和语言也进不去。

### 3.3 设置 · 外观（新）

| 项 | 交互 |
|----|------|
| 主题 | 三个并排选项：浅色 / 深色 / 跟随系统。当前项高亮。复用 `useTheme`，不再用顶栏循环。 |
| 语言 | 列表点选，复用 `useI18n` / 已注册 locale 插件。 |

本轮 **不** 把完成提示音放进来（见需求 D-03，默认 C）。

### 3.4 设置 · 模型 / 技能 / 插件

把现有 `ModelsConfig` / `SkillsConfig` / `PluginsConfig` 嵌进设置内容区。

- 关闭设置 = 关闭当前分区（与今天关弹层相同的刷新副作用：例如关模型后 `modelsRefreshKey++`）。
- 不要三个全挂载：只渲染当前分栏，避免设置一打开就拉三套数据。
- 各组件内部的「关闭」与外壳关闭对齐：统一成设置页右上角关闭；内层若已有关闭钮，改为调用外壳 `onClose`，避免双套窗口。

### 3.5 聊天顶栏（推荐落地 = 需求 D-01 方案 B）

**移走（进设置）**

- 主题按钮
- 语言按钮及语言下拉（`activeTopPanel === "language"`）

**保留为布局 / 状态（仍在顶栏，不进设置）**

- 侧栏开关
- 项目信任提示（安全，必须看见）
- 会话用量 / 费用（状态，不是配置）
- 文件面板开关

**会话工具：不再平铺，收进「会话」溢出**

一个带文字的按钮「会话」（窄时只留图标 + title），菜单项：

1. 完整历史
2. 生成标题
3. 分支（点开后仍用现有 `BranchNavigator` 面板）
4. 系统（点开后仍用现有系统提示面板）

移动端：现有「⋯」继续当会话工具抽屉；从中去掉主题 / 语言。主题语言只走设置。

> **注意：** 若 Gate-S 选 D-01-C，则桌面四项仍平铺，只搬家主题语言。方案其余部分不变。

## 4. 关键交互

1. **打开设置**：左下「设置」；焦点进入面板；Esc / 遮罩 / 右上关闭。
2. **分栏记忆**：`sessionStorage` 记最后一分栏即可（刷新浏览器重置可接受）。不写新后端。
3. **未选项目**：外观、模型可用；技能 / 插件分栏禁用并说明原因（与今天按钮 disabled 一致）。
4. **空状态文案**：`workspace.addModels` / `workspace.stepModels` 改为指向「左下角设置 → 模型」。
5. **主题**：设置里改主题仍使用现有圆形扩散动画（若 `toggleTheme` 需要坐标，用选项按钮中心）。

## 8. 风险

| 风险 | 处理 |
|------|------|
| 三个 Config 自带独立 modal 外壳，嵌入后双滚动条 / 双关闭 | 加 `embedded` 或拆出内容区；施工时先读三文件头部结构再改 |
| 用户期望「分支」进设置 | 方案写明拒绝理由；若坚持走 D-01-A，设置页需按「当前会话」动态禁用，体验差 |
| 窄侧栏装不下「设置」二字 | 响应式：文字可藏，齿轮 + title 必须在 |
