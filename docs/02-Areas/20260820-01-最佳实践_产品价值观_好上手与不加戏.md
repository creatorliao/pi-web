## 1. 两条原则

### 好上手

站在已经会用 VS Code、Cursor、JetBrains、资源管理器的人这边。他们带来的习惯是资产，不是要被教育的对象。

- 先问：同类软件这件事通常怎么做？
- 能沿用就沿用（欢迎选项目、Open Recent、对话框 Esc 关闭、系统 UI 字 + 本机等宽字）。
- 只有现成习惯明显伤害本产品时，才偏离，并在方案里写清「为什么不能跟」。

### 完整但不加戏

功能要能走完，不要靠残缺路径「先顶上」。完整指主路径、失败恢复、已有进阶入口（深链、自定义目录）还在；不是把能想到的偏好和装饰都做上。

- 先问：没有这一层，人是否仍能办完事？
- 能办完就不要加：第二次确认、记住勾选、假三栏、步骤教练、卡片上预拉用不到的 Git。
- 「少做」不是砍能力：该有的选、换、打开本机目录，必须都在，可以共用一套 UI。

两条一起用：好上手决定**形态像谁**；不加戏决定**做到哪一层停**。

---

## 2. 怎么做（拍板顺序）

1. 写出人要完成的一件事（例如：打开工具并进入某个目录）。
2. 列出两三个主流软件的对应开法，选最不需要学习的那个。
3. 列出「没有也能办完事」的附加层，划掉。
4. 检查主路径、失败、进阶入口是否仍闭环。
5. 再写方案或改代码。

## 3. 正反例

| | 好上手 | 完整但不加戏 |
|--|--------|----------------|
| 正 | 冷启动用欢迎选项目（JetBrains）；左栏只显示项目名（VS Code 窗口标题） | 欢迎页与切换模态共用一套卡片；`?session=` 仍直达 |
| 反 | 左上角箭头教「去设置加模型」 | 欢迎页再加「下次自动进入」勾选 |
| 反 | 路径用 Web 字体换脸，和本机 IDE 并排违和 | 启动画不能点的假三栏，只为了「像已经进去了」 |
