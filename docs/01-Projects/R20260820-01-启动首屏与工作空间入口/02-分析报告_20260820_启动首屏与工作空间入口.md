## 1. 结论先说

用户看到的不是「偶发闪一下」，而是**当前启动时序把中间态画成了成品界面**：

| 观感 | 代码里实际发生的事 | 是不是缺陷 |
|------|-------------------|------------|
| 白屏 | `page.tsx` 用 `Suspense` 包整棵客户端树；`AppShell` 全是 `"use client"`。首包未到 / 水合未完成时，视口只有 `globals.css` 的 `--bg`（浅色几乎是白） | 是。没有启动壳 |
| 路径先露出来 | 会话列表一返回，侧栏立刻 `setSelectedCwd(最近项目[0])`，路径胶囊马上有字；文件树、对话、模型此时往往还空着 | 是。业务数据比 chrome 齐得早 |
| 「初次使用 / 去加模型」 | `showPlaceholder && !activeCwd` 时画「开始使用」两步清单。**不查询模型是否已配置**。冷启动 `activeCwd` 在列表返回前是 `null`，已配置用户也会闪到这段 | 是。把「还没选 cwd」当成「从没设过」 |
| 一进来就是某个目录 | 有意设计：`getRecentProjects()[0]` 自动选中（最近改过的项目） | 对「继续昨天」友好，对「每次想换地方」不友好 |

路径口述「右上角」：当前实现里**最显眼的路径条在左栏项目选择器**（与截图一致）。编辑器布局下，文件列页签下细栏也会写路径（R-03 D26）。露底时两处都可能「字比架子先到」。分析按这两处记，不改用户原话。

## 2. 当前使用体验（已有能力，按人怎么走）

打开工具之后，人实际经历的是一条**隐式自动进入**，而不是「选地方再干活」。

```text
打开 / 
  → 白/浅底，三栏未齐
  → 会话列表返回
  → 自动选最近项目 cwd（路径条有字）
  → 尽量恢复该项目上次会话（localStorage last-open-by-workspace）
  → 文件树、对话、底栏 Git 陆续补齐
  → 若中间某一帧还没有 cwd：对话列左上角画出「开始使用」箭头清单
```

工作中途换项目（R-07 路径 A–C）仍然成立：

- 左栏顶部一条窄按钮，点开是**路径字符串下拉**，超过 8 个项目才出现筛选。
- 「自定义路径…」另开目录选择器；「使用默认目录」直接建 `~/pi-cwd-当天`。
- 点另一条会话会把 cwd 改成那条会话的目录。
- Git 顶层可换 worktree（左栏或底栏）。

这些能力**够用，但不符合「先选再进」**：没有预览卡片、没有进入确认、默认替人做了第一步。

## 3. 根因（按问题）

### 3.1 白屏

- 根布局只注入主题脚本和 `Noto_Sans_Mono`（`display: "swap"`），没有应用壳 HTML。
- 首页没有服务端骨架：`Suspense` 的 fallback 未提供，子树挂起时就是空内容 + 白底。
- 浅色 `--bg: #ffffff` 与「还没画栏」叠在一起，就是用户说的白屏。

### 3.2 露底（路径、半截 chrome）

`SessionSidebar` 首次加载：

```text
allSessions.length > 0 且 selectedCwd === null
  → setSelectedCwd(projects[0].root)
```

选择器按钮在 `selectedCwd` 有值时立刻用等宽字体画出整段路径。此时：

- 文件浏览器可能仍是折叠标题或空树；
- 对话列可能仍是占位或引导；
- 底栏项目名 / Git 可能还没拉到。

人的知觉是：**一块路径先贴在界面上，架子还没到。**

### 3.3 引导误出

`AppShell` 对话列空态：

| 条件 | 画出的东西 |
|------|------------|
| `showChat` | 正常 `ChatWindow` |
| `initialCwdStatus === "validating"` | 「正在打开工作区…」 |
| `initialCwdStatus === "error"` | 「无法打开工作区」 |
| `showPlaceholder && activeCwd` | 「从侧边栏选择一个会话」 |
| `showPlaceholder && !activeCwd` | **「开始使用」+ 选项目 + 去设置加模型** |

`showPlaceholder = initialSessionRestored && !showChat`。无 `?session=` 时 `initialSessionRestored` 一开始就是 `true`。`showChat` 要等 `selectedSession` 或 `activeCwd`。侧栏还没把 cwd 抬上来的那几帧，走最后一行。

文案 `workspace.addModels` **从不读** `GET /api/models`。模型早就在 `models.json` / 登录态里，只要 cwd 未到，第二步仍会写「去加模型」。

这不是设置丢失，是**用启动竞态驱动了零配置文案**。

### 3.4 默认工作空间

`getRecentProjects()` 按会话 `modified` 取每个项目最新一条，再按时间倒序。`[0]` 就是「最近动过的仓库」。产品假设：回来继续干这件事。

用户假设：打开工具 = 选今天要进的目录。两个假设冲突。最近项目经常不是本次目标（例如昨天在 `prompts-extract-master`，今天要进 `pi-web`）。

### 3.5 切换界面偏「命令行清单」

下拉每一行是等宽长路径，认知负担是扫字符串，不是认项目。没有卡片、没有「上次在这儿做了什么」、没有进入前的停顿。和 IDE「最近打开的文件夹」或「Open Folder」 mag 比，密度高、辨识度低。

## 4. 差距表

| 人的预期 | 现在 | 差距 |
|----------|------|------|
| 打开后先看到完整窗或选择闸门 | 白底 → 碎片控件 → 忽然齐 | 无启动门闩、无骨架 |
| 路径属于已进入的工作区 | 路径是自动选中的副作用，先于「进入」 | 把「列表到了」当成「人已经在里面」 |
| 引导只在真没配过时出现 | 无 cwd 的中间帧 = 引导 | 状态机缺「hydrating」 |
| 我选目录再干活 | 最近项目自动进入并恢复会话 | 缺显式入口闸门 |
| 换项目像翻卡片 | 窄下拉 + 长路径 | 选择 UI 与任务不匹配 |

## 5. 体验原则（本专题设计立场）

1. **未就绪等于未展示业务。** 骨架可以在，路径、引导、空态清单不可以单独先到。
2. **零配置 ≠ 零 cwd。** 前者看模型/鉴权；后者看人有没有选目录。
3. **进入是一次明确动作。** 自动恢复只允许：URL 指定、或用户勾过「下次直接进入」。
4. **选择器只有一套。** 启动闸门和运行中切换是同一组件的两种打开方式，避免两套列表两套排序。
