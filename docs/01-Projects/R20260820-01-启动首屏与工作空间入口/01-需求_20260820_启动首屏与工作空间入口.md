## 目标（Why + What）

- **业务目标**：打开 Pi Web 时，人先感到「工具已经准备好」，再进入**自己选的**工作目录；不要被半成品界面和错误引导打断。
- **用户价值**：冷启动像 IDE，不像网页在拼装；换项目像选一张卡片，不像被塞进最近用过的那个目录。
- **成功标准**：
  1. 从点开到可操作，中间只有一种完整壳（骨架或闸门），没有白闪、没有控件先露后齐。
  2. 已配置过模型 / 项目的人，看不到「开始使用 / 去设置里加模型」。
  3. 无 URL 指定会话或目录时，先选工作空间再进主界面；默认最近项目不再自动接管整屏。
  4. 工作中途换项目，也走同一套卡片选择器，不再只靠窄下拉。

## 用户原话（保留语义，不改成实现句）

1. 一启动先白屏；还没加载完就露出东西，有露底感。
2. 路径那一块尤其明显（口述「右上角」；实现对照见分析报告）。
3. 左边会冒出「设置模型 / 初次使用」一类提示；人已经配好了，不该再出。
4. 切换工作空间不方便；希望点开后是弹框 + 若干卡片，选路径再进入。
5. 不要一进来就掉进默认工作空间——那个往往不是这次要做的。
6. 以前打开过、但本机目录树里已经没了的文件夹，选择器里不该再出现。

## 功能需求（In Scope）

## 非目标（Out of Scope）

- 不改三栏槽位、对话顶栏、历史分组（R-03）。
- 不改 Composer / 底栏（R-01、R-13 冻结面）。
- 不在本夹改字族、抗锯齿、font-display（[R-02](../R20260820-02-字体与文字渲染/01-需求_20260820_字体与文字渲染.md)）。
- 不做 VS Code 式多根工作区（多 folder workspace）；仍是「一个 cwd / 一个项目」。
- 不重做 worktree 创建/删除；闸门里只消费已有列表。
- 不引入新的 Toast 气泡体系。

## 约束

- 侧栏仍读 `~/.pi/agent/sessions`；闸门的「最近项目」复用 `getRecentProjects()`，不要第二套排序。
- 选目录仍走 `POST /api/cwd/validate` 与 `allowFileRoot()`，安全边界不变。
- 并行多会话结论仍以 R-07 为准：换项目不杀后台会话。
- 文案走 i18n；引导句只在 F-03 条件成立时出现。

F-12 **不删** `~/.pi/agent/sessions` 里的 jsonl，只从选择器消失。目录重新出现后，下次拉列表会再进网格。
