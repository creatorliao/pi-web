## 目标（Why + What）

- **业务目标**：把「多项目同时跑」从内核事实变成用户能管得住的体验。人可以一边盯项目 A 的流式输出，一边再开项目 B；A 不会被界面覆盖掉，也能一眼看见谁还在跑、一键回到刚才那条。
- **用户价值**：像用 IDE / 浏览器一样同时开几个仓库干活，而不是在同一个壳里「切走就看不见、只能凭侧栏小点猜后台还在不在」。
- **成功标准**：
  - 打开另一个项目时，当前正在看的项目默认还在（新开一层，不覆盖），除非用户明确关掉当前。
  - 任意时刻能从固定入口看到：有哪些项目、哪些会话在跑。
  - 能从该入口（或前进/回退/最近关闭）快速回到刚才的项目与会话，接上还在流的输出。
  - 对照 OpenCode Desktop 现行页签逻辑，写清可抄与不可抄；本仓方案不发明第二套并行运行时。

## 用户原话（问题与诉求，原意保留）

1. 点开一个新项目时，希望是**新的浏览器页签**，不要覆盖当前页签；除非用户想关当前。
2. 要有良好的**前进 / 退出**机制：能从某一个地方看到、快速切回刚才的项目，看正在跑的那条。
3. 核心诉求是**多项目同时并行**；从用户角度更好管控多个项目、看见运行状态、切换过程体验好。
4. 参考 OpenCode 当前产品逻辑（尤其 Desktop 已支持多页签并行），对照 `D:\code\opencode` 最新代码，评估本仓如何实现类似能力。
5. 先建主题夹，记录需求与问题，再出调查研究分析报告。

## 非功能需求

- **性能**：多前台同时订阅 SSE 时，不能拖垮同一 Node 进程的主路径；方案须写并发上限或「后台只保留 running 点」。
- **兼容性**：Win / 本机浏览器；pi-web 是 Web，不是 Electron。不能假装有原生窗口页签。
- **安全**：不新开文件系统浏览面；allowed-roots 仍按现有会话 cwd 累加。
- **价值观**：好上手（对齐浏览器 / IDE 开窗口习惯）；不加戏（不画第二套项目列表、不预加载用不上的 Git）。

## 非目标（Out of Scope）

- 不包括：本轮改代码、拆工作包、提 PR。
- 不包括：每项目一个独立 Node / 独立 `pi` 进程（R-07 的 P3）。
- 不包括：单页并排两个 ChatWindow（R-07 的 P2）作为默认方案。
- 不包括：复刻 OpenCode 的 remote workspace、WSL sidecar、子智能体 Task。
- 不包括：改启动欢迎卡怎么选目录（仍归 R-01）。
- 推迟到方案论证：具体快捷键、是否做应用内页签条、是否真用 `window.open`。

## 约束

- **技术栈**：Next.js App Router + 进程内 `AgentSession`（`globalThis.__piSessions`）。并行粒度已是 sessionId。
- **前序事实**（R-07）：换空间不 abort；后台可跑；一个浏览器页签只渲染一个 `ChatWindow`。
- **对照仓**：`D:\code\opencode`，Desktop / App 版本 **1.18.18**（调研日无稳定 `v2.0.0` tag）。
- **时间**：本次只文档。
- **PM 铁律**：先文档后代码；等用户确认需求后再进路线图 / 方案论证。

## 待决项（@待确认）

- [ ] **@待确认-1 开新项目的「新层」是什么？**  
  A. 真实浏览器页签（`window.open` + `?cwd=` / `?session=`）  
  B. 应用内页签条（抄 OpenCode titlebar，仍在同一个浏览器页签里）  
  C. A 为默认，B 以后再说  
  **推荐 C**：Web 产品对齐「再开一个浏览器页签」成本最低，且 R-07 内核已支持；应用内条是桌面壳的习惯，搬过来等于再造一套 Chrome。

- [ ] **@待确认-2 从欢迎卡 / 切换器点另一个项目，默认行为？**  
  A. 总是新开一层（当前层保持）  
  B. 当前层是欢迎页则就地进入；已经在项目里则新开  
  C. 修饰键分流：普通点击覆盖（现状），Ctrl/中键新开  
  **推荐 B**：冷启动还是一张欢迎卡进一个项目（好上手）；已经在干活时再开别的项目才新开，避免「第一次选项目也弹出第二个页签」。

- [ ] **@待确认-3 「回切刚才」的主入口？**  
  A. 浏览器自身：页签栏 + 历史后退 + 窗口标题=文件夹名（已有）  
  B. 应用内「进行中」一条（只列 running / 刚关的，不加第二套完整项目树）  
  C. A + 侧栏/底栏已有的跨项目运行点，做到可点击跳转（现在运行点在，跳到**别的项目**会覆盖当前）  
  **推荐**：若选浏览器页签（待确认-1=A/C），主入口就是浏览器页签，应用内只补「点运行中会话时新开或确认覆盖」；不要再做完整项目树。
