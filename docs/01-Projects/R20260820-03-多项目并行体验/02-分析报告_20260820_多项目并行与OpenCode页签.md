## 1. 答复（给决策用）

| 问题 | 答复 |
|------|------|
| 现在两个项目能不能同时跑？ | **能。** 同一 Node 里多条 `AgentSession`，cwd 可以不同。换项目不 `abort`。 |
| 为什么体验仍像「被覆盖」？ | 浏览器**一个页签只有一个壳、一个 `ChatWindow`**。`enterWorkspace` 会拆掉当前对话视图、`router.replace("/")`，人眼前只剩新项目。后台还在跑，但前台被换走了。 |
| OpenCode 是不是「新开一个浏览器页签」？ | **不是。** Desktop 是 Electron **窗口内**的 Chrome 式页签条。点开项目 / `Mod+T` 是往**同一窗口**追加一条 Session/Draft 页签，再 `navigate` 过去。当前页签还在条上，可以点回去。 |
| 并行发生在哪？ | OpenCode 与 pi-web 一样：**Server 里多 Session 同时 busy**；UI 只决定你此刻看哪一条。OpenCode 多页签的增量是「多条前台身份同时挂着」，不是再做一套内核。 |
| 本仓最小对齐？ | 不要先抄 Electron 页签条。Web 上对齐用户原话的是：**再开一个浏览器页签**（深链 `?cwd=` / `?session=` 已存在），当前页签不动。内核不用新写。缺的是产品约定：从选择器打开时 `window.open`，以及点「别人家的运行中」时不要默默覆盖。 |

一句话：**内核已经并行；痛点是「一个浏览器页签 = 一台壳」，换项目等于换掉你盯着的那扇窗。OpenCode 用应用内页签条解决同一问题；pi-web 是浏览器应用，用系统页签更短、也更符合「好上手」。**

## 2. 用户问题拆开（现象 / 根因 / 已有半成品）

### 2.1 开新项目覆盖当前

**现象**：已经在项目甲看流式（或等结果），再从欢迎卡 / 切换器进项目乙，甲的对话从眼前消失。

**根因（界面，不是内核）**：

```843:905:components/AppShell.tsx
  const handleCwdChange = useCallback((
    cwd: string | null,
    ...
  ) => {
    // ...
    setSelectedSession(null);
    setSessionKey((k) => k + 1);  // 拆掉当前 ChatWindow
    // ...
    if (currentProject !== newProject) {
      setFileTabs([]);
      restoreWorkspaceContext(newProject);
    }
    router.replace("/", { scroll: false });
  }, [...]);
```

`enterWorkspace` → `handleCwdChange`：**同一文档、同一 React 树**改 `activeCwd` / `selectedSession`。没有 `window.open`，也没有应用内页签栈。

**没被覆盖的**：`__piSessions` 里甲的包装器、`.jsonl`、侧栏 `/api/agent/running` 的亮点、完成后的提示音 / 通知（`ChatWindow` 卸了，完成音挂在壳上）。

### 2.2 回切「刚才那个正在跑的」

**已有**：

- 窗口标题：`{文件夹名} - Pi Web`（`AppShell`）。两个系统页签时，浏览器页签栏能分出项目。
- 侧栏会话行：当前项目内的 running 点。
- 工作空间选择器：跨项目 `running` / `unread` 计数；收起时「别的项目有活动」打点（`hasOtherWorkspaceActivity`）。
- 再点回该会话：`GET /api/agent/[id]` 见 `isStreaming` 则重连 SSE。

**缺口**：

- 选择器里点另一个项目，仍走 `enterWorkspace`，**覆盖当前层**。
- 没有「刚关的项目/页签」栈（OpenCode 的 `reopenClosedTab`）。
- 进入项目后常 `replace` 成 `/` 或 `?session=`，**没有稳定的 `?cwd=` 留在地址栏**（R-01 为欢迎闸门故意不把 cwd 写进 URL）。结果：系统后退键不是「回到上一个项目」，而是容易回到欢迎相位。
- 前进/后退因此**不能**当多项目任务栈用。这是用户要「良好前进和退出」时，现状对不上的那一层。

### 2.3 管控多个项目的运行态

进程内已经全量扫 running。UI 把会话列表**滤成当前项目**（`sessionsForProject`），所以「全世界谁在跑」只压缩在选择器徽章上，不能像 OpenCode 页签条那样一眼扫过甲、乙、丙三条。

## 3. OpenCode Desktop 页签：产品逻辑（用户看见什么）

对照版本：本机 `D:\code\opencode` 全包 **1.18.18**。既有「OpenCode 并行调研」写的是 Session / 子智能体 / worktree；**多页签并行**是另一条产品面，入口在 `packages/app`。

### 3.1 一句话

**一个 Electron 窗口 = 一条页签条 + 一个 Home。** 页签是「某 Server 上的一条 Session，或某个目录上的新建草稿」。打开另一个项目 = **再挂一条页签并跳过去**，旧页签还在。Agent 跑在本地 sidecar Server 里，切页签只换路由。

用户不会看到「新开一个 Chrome 页签」。Desktop 自己画了 Chrome 那种条。

### 3.2 用户操作对照

| 用户要做的事 | OpenCode 怎么做 | 快捷键（代码注册） |
|--------------|-----------------|-------------------|
| 从 Home 打开项目，开新对话 | `openProjectNewSession`：`projects.open` + `tabs.newDraft`，**push 新页签** | Home 上点项目 / New |
| 再开一条（同目录或当前会话目录） | `openNewTab` → 又一个 Draft | `Mod+T` / `Mod+N` |
| 看另一个已开会话 | 点页签；`tabs.select` → `navigate(href)` | 页签条 |
| 回 Home（项目宫格），不关页签 | `toggleHome`：记住当前页签，路由 `/`；再按回到 recent | `Mod+B` |
| 关掉当前页签 | `closeTab`：记入关闭栈（仅 Session），切到右邻否则左邻，没有则 Home | `Mod+W` |
| 找回刚关的 | `reopenClosedTab`，最多 25 条 Session | `Mod+Shift+T` |
| 看这条还在不在跑 | 页签头像：`session_working` 转圈；未读 / 要授权 / 有提问则 unread | 页签条上直接看 |

关闭草稿页签**不**进重开栈（草稿 persist 会删，重开也是空的）。清理路径（会话没了、归档、Server 断开）走 `removeTab`，不进关闭栈。

### 3.3 页签不是「一个项目一个页签」

类型在 `packages/app/src/context/tabs.tsx`：

- `SessionTab`：`{ server, sessionId }`
- `DraftTab`：`{ draftID, server, directory, worktree? }`

同一项目可以挂很多页签（很多 Session）。不同项目也可以同时挂在同一条上——因为每条都自带 `directory` / session 所属目录。

所以 OpenCode 的并行页签粒度是 **会话（+ 未发出的草稿）**，不是「项目窗口」。项目只是 Session 的目录属性；Home 才是项目选择面。

这和用户说的「一个浏览器页签一个项目」**相近但不相同**：

- 相近：开新项目不会拆掉旧页签。
- 不同：一条应用内页签通常是一条对话，不是「整个三栏项目 IDE」。

### 3.4 Home 与页签的前进/退出

Home **不是**页签。`toggleHome`：

- 在 Home：跳回 `tabs.recent` 记住的那条。
- 在某条页签：记下它，`navigate("/")`。

这就是他们的「退出到项目宫格 / 再进刚才那条」，**不依赖浏览器历史**。页签条本身承担「看见所有打开的、点谁到谁」。

### 3.5 运行态怎么画在页签上

`session-tab-avatar.tsx` + `project-avatar-state.ts`：

- `loading` = 该 `sessionId` 的 `session_working`（且当前没有待处理权限/提问）。
- `unread` = 要授权、要回答，或通知里的 unseen。

用户扫页签条就能区分：转圈=还在跑；红点/未读=要你回去处理。不必先切进会话。

## 4. OpenCode 页签：技术切片（实现怎么做的）

### 4.1 状态存在哪

`tabs.tsx` 用 `Persist.window("tabs")` / `tabs.recent` / `tabs.info` / `tabs.closed`。

`persist.ts` 的 `windowStorage(windowID)` → `opencode.workspace` 一类的 **按窗口分文件**。Electron 每个窗口一份页签条；刷新窗口还能回来。

页签内存（composer 等）用 `tab-memory`，按 `tabKey` 隔离。切走不销毁 Session 运行时。

### 4.2 打开 = append + navigate，不是 replace 掉 store

```209:221:D:/code/opencode/packages/app/src/context/tabs.tsx
      async newDraft(...) {
        const draftID = uuid()
        const tab = { type: "draft" as const, draftID, ...draft }
        ...
        await startTransition(() => {
          setStore(produce((tabs) => { tabs.push(tab) }))
          navigate(draftHref(draftID))
        })
        return tab
      },
```

`addSessionTab`：已有相同 `tabKey` 则复用，不重复加。

Home 打开项目（`home-controller.ts`）：

```49:54:D:/code/opencode/packages/app/src/pages/home/home-controller.ts
  function openProjectNewSession(conn, directory) {
    ctx.projects.open(directory)
    ctx.projects.touch(directory)
    void tabs.newDraft({ server: ServerConnection.key(conn), directory })
  }
```

**没有**「先卸掉当前 Session 再把 cwd 改成新目录」这一步。

### 4.3 关掉当前之后去哪

`closed-tabs.ts`：`nextTabAfterClose` = 右边否则左边；若关的是当前且没有邻居 → `navigate("/")`。

用户关的 Session 进栈，`Mod+Shift+T` 按原 index 插回去并 `navigateTab`。

### 4.4 和「并行执行」的关系

Desktop 主进程 fork sidecar（既有调研 §3.4）。页签条只订阅、切路由。两条页签同时 busy，是 Server 上两个 Session 的 `session_working`，不是两个 Electron 渲染进程各跑一套模型循环。

**不该抄进 pi-web 的**：WSL 多 Server、workspace 控制面、`sessionWarp`、按窗口的 sqlite persist、Solid 路由整套。

**可抄的产品约定**：打开=追加身份；Home/选择器与「当前对话」分离；关闭有落点；关闭栈；页签上画 working/unread。

## 5. pi-web 对照（现在差在产品层）

| 层 | OpenCode Desktop 1.18.18 | pi-web 现状 | 差距 |
|----|--------------------------|-------------|------|
| 运行时 | sidecar 多 Session | `globalThis.__piSessions` 多包装器 | 已对齐，不必再做内核 |
| 前台身份 | 窗口内 N 条 Session/Draft 页签 | 1 浏览器页签 × 1 `ChatWindow` | **主差距** |
| 开新项目 | push 页签，旧的留在条上 | `enterWorkspace` 改同一壳 | 覆盖感的来源 |
| 看见谁在跑 | 每页签头像 working | 当前项目列表 + 选择器数字/点 | 能知道，不能并排盯 |
| 回切 | 点页签 / Home toggle / 重开关闭栈 | 再选卡片或会话（覆盖当前） | 没有「刚才那层还在」 |
| 系统页签 | 一般就一个 Electron 窗口 | 用户**可以**自己再开一个 `localhost` 页签盯另一条 `?session=` | 内核支持，产品没当主路径 |
| 地址栏 | 应用内路由 `/session/...`、`/new-session?draftId=` | `?session=` 深链；进项目后常丢掉 `?cwd=` | 系统历史不是项目栈 |
| 窗口标题 | 会话标题等 | 文件夹名 `- Pi Web` | 若真用多浏览器页签，标题已经够认 |

## 6. 若本仓要类似能力：怎么实现（只论证）

前提：不新写 Agent 运行时。价值观：好上手跟浏览器/IDE；不加戏不第二套项目树。

### 6.1 路线比较

| 路线 | 用户体感 | 和现核 | 代价 | 是否贴用户原话 |
|------|----------|--------|------|----------------|
| **W1 系统浏览器页签** | 点新项目 → `window.open` 带 `?cwd=` 或上次 `?session=`；当前页签不动。关页签=退出该项目前台。浏览器页签栏=任务条。 | 已支持两页盯两个 sessionId | 选择器要改「开法」；深链与欢迎闸门（R-01）要约定：新页签带 `?cwd=` 是否跳过欢迎 | **最贴**「新的浏览器页签」 |
| **W2 应用内页签条** | 抄 OpenCode titlebar：壳里 N 个 Chat 身份 | 要改 AppShell 单例 `selectedSession` / `sessionKey`；每页签自己的 SSE 或切走关 SSE（现在已是关 SSE 不停核） | 重：排序、溢出、关闭栈、草稿、和现有文件页签（`TabBar`）重名 | 像 Desktop，但 Web 上是第二套 Chrome |
| **W3 只改回切、仍覆盖** | 选择器运行中可点；历史栈「上一个项目」 | 小改 | **达不到**「不要覆盖」 | 不满足 F-05 |

**推荐（论证，未拍板）：W1 为 v1。** 与 R-07 P1、待确认-1 推荐 C 一致。

W2 仅当出现这些才值得：用户强烈要「一个浏览器页签里来回点、不要一堆 Chrome 页签」；或以后做桌面壳。现在做 W2 违反「不加戏」。

### 6.2 W1 最小产品切片（供日后 PM-54，本轮不施工）

1. **已经在项目里**时，欢迎/切换器点**另一个**项目：`window.open` 同源 URL，带该项目的深链；当前 `document` 不调用覆盖型 `enterWorkspace`。
2. **冷启动欢迎页**（还没有当前项目）：仍就地进入（R-01），不要弹出第二个页签。
3. 深链：优先恢复 `pi-web:last-open-by-workspace` 的 session → `?session=`；没有则需要一条「只打开项目、空对话」的稳定 URL。今日 `?cwd=` 会走 deeplink 并忽略 session——可复用，但要和 R-01「刷新不要误跳过欢迎」一起设计：新开的是**有意图的深链页签**，不是冷启动。
4. `document.title` 已是文件夹名，系统页签可辨。
5. 点**其他项目**的 running 会话：与 1 相同，新开 `?session=`，或明确「在当前页打开（会离开甲）」。
6. 前进/退出：系统页签关闭 = 退出该前台；浏览器历史只服务**同一项目内**（会话切换）。不要承诺系统后退 = 上一个项目，除非以后把项目切换改成 `pushState` 且不拆运行中视图。
7. 可选增量（仍不加第二套列表）：选择器徽章可点击 → 新开；侧栏「其他项目有人在跑」点一下展开**仅 running 行**（不是全量项目树）。

### 6.3 不该做的

- 为「看起来并行」在欢迎卡预拉双会话预览。
- 每个项目拉起一个 Node。
- 单页并排两个 `ChatWindow`（P2）当 v1。
- 再做一套和应用内文件 `TabBar` 并列的「项目页签」，却同时再用 `window.open`——两套开法。
- 把 OpenCode 的 Draft persist / 按窗口 sqlite 整段搬来。

### 6.4 风险（W1）

| 风险 | 说明 |
|------|------|
| 弹窗拦截 | `window.open` 必须跟在点击里，不能 async 之后再开。 |
| 两页抢同一 session | 两个页签打开同一 `?session=`：输入焦点、SSE 双订。R-07 已点名。v1 可允许多订（只读流），或后开的页签提示「已在另一页打开」。 |
| 欢迎闸门 | 新页签带 `?cwd=` 必须进 ready，不能再卡欢迎；无 query 的 `/` 仍是冷启动。 |
| 配额 | 多前台同时流式会叠 SSE + 渲染；running 本身不是问题。 |
| 和 R-01 选择器改版 | 09 方案若还在等 Gate-S，开法（就地 vs 新页签）要写进同一选择器，避免两套卡片。 |

## 7. 价值观对照

- **好上手**：浏览器里「再开一个页签」；IDE 里「再开一个窗口」。OpenCode 在 Electron 里把窗口内页签做成了 Chrome。pi-web 已经活在 Chrome 里，不必再画一条。
- **不加戏**：后台跑 + running 点已经是半闭环。要补的是「打开时别拆当前层」和「点运行中能回去」，不是宫格、教练、双列表。
