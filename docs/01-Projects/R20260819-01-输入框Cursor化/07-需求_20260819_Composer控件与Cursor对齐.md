## 1. 目标复述（Why + What）

- **业务目标**：智能体输入框的使用体验、外观、状态变化与 Cursor Composer **相对一致**，用户换产品时不必重新学「按钮在哪、箭头朝哪、生成中怎么停」。
- **用户价值**：写提示时，模型/思考、压缩、附件、发送、停止都在 **同一块输入框里**；工具权限与提示音在窗口底栏固定可点；对话列变窄时仍能发送。
- **成功标准**：见 §3 F-11～F-16；对照 Cursor 截图与本仓手验清单（09-方案 §7）。

---

## 2. 用户原话（四条，不改写意图）

1. **图标方向搞错了**（发送箭头应对齐 Cursor：向上，不是向右）。
2. **模型名称和思考深度放在一起**，严格按照 Cursor 输入框设计。
3. **压缩**（本套工具独有）设计进输入框内部；对话宽度收窄时，框内这一排从左往右隐藏，**上下文圆环先藏**。
4. **模型正在返回时，发送按钮中间是方块**；不同状态图标要变对。
5. **（修订）** 喇叭已归窗口底栏；**工具预设 default 也归底栏**，点击底栏项弹出与现 Composer 相同的预设列表。不再画在输入框里。

## 3. 功能需求（In Scope）

| # | 需求描述 | 优先级 | 来源 |
|---|----------|--------|------|
| F-11 | 空闲可发送：圆形发送钮内为 **向上箭头**；无内容时弱化/禁用，有内容时强调 | 必做 | 用户 1 + Cursor |
| F-12 | 生成中：同一圆形主按钮变为 **停止**（中心实心方块），点击中止当前回复；不再用框外大红「Stop」文案条作为主停止入口 | 必做 | 用户 4 |
| F-13 | 模型与思考深度 **视觉与交互成组**：左侧一组触发器，观感对齐 Cursor「胶囊 + 思考/速度文案」；思考档位与模型切换在同一套菜单层级里可达（见方案选项） | 必做 | 用户 2 |
| F-14 | **压缩**画在输入框圆角边框之内（图标+可选文案）；不在框外另起一条地面。工具预设与喇叭 **不** 在 Composer 重复 | 必做 | 用户 3 + 修订 |
| F-15 | 对话列变窄：框内这一排 **从左到右依次隐藏**；**上下文圆环优先隐藏**（用户点名） | 必做 | 用户 3 |
| F-16 | 明确各运行态图标：空闲空/空闲可发/生成中停止；压缩进行中仍用现有方块语义，不与发送停止抢同一视觉位置 | 必做 | 用户 4 |
| F-17 | Composer **删除** 喇叭与工具预设入口（迁出后禁止双入口） | 必做 | 用户修订 + R-13 |

## 4. 非功能

- 只用现有 CSS 变量（`--bg / --border / --accent / --text-muted` 等）。
- 中文 IME、Enter 发送、草稿、技能行内高亮（路线 C）不得回归。
- 窄列可用键盘发送（Enter）与 Esc 停止（已有则保留）。
- 不作 `next build`。

## 5. 非目标

- 不做 Cursor 的 **Agent / Ask** 模式切换（R-01 已排除）；禁止画一颗假「Agent」胶囊充数。
- 不做 Cursor **Fast** 开关的语义对标（那是 Cursor 速度档；本仓「默认」是工具预设）。
- 语音真转写、Review / Undo 真逻辑：仍只画或不做。
- 不把模型、思考深度迁进窗口底栏（R-13 D1 仍成立）。
- 不在 Composer 菜单里再藏一版工具预设（Options 不再映射 Fast/default）。
- 不改技能 `/` `@` 行内变色方案。
