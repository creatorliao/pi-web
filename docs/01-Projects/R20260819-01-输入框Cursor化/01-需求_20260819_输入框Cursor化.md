## 需求勘误（对照用户补充 + 截图）

| 曾误解 | Cursor 实际（本次以用户说明为准） |
|--------|-----------------------------------|
| 技能是输入框 **顶上** 一排胶囊 | 技能就在 **输入框正文里**，选中后 **就地变色** |
| 芯片条 + 透明 textarea + 叠加层 = 2～3 份 | **永远只有一份**提示（一颗着色胶囊） |
| 选技能后整框被换成 `/skill:name` | 胶囊后可继续写 **指令/说明**，同一段话里混排 |
| `/` 只能在输入开头触发（当前代码） | **正文任意位置** 打 `/` 都能出技能列表 |
| 一个框一颗技能 | **同一输入框可多颗**技能，中间夹普通字 |

顶栏「N Files / Undo / Review」是 **本轮写出文件**，与技能胶囊无关，不要再混进 F-03。

## 目标（Why + What）

- **业务目标**：技能交互贴近 Cursor Composer：行内变色、一份显示、可后接指令、任意位置 `/`、可多颗。
- **用户价值**：写长提示时随时插技能，不用清空重来；看见的就是将发给模型的那串字。
- **成功标准**：见 F-03～F-03e、F-09、F-10；颜色走项目变量。

## 非功能需求

- 视觉：只使用 `--bg / --border / --accent / --user-bg` 等现有变量。
- IME：中文选词、回车上屏不得坏。
- 发送契约：仍是纯文本，含 `/skill:name` 与后接说明、`@path`。
- 不引入 Tiptap 除非路线 C 被证伪。

## 非目标

- Agent/Ask 模式、语音真转写、Review/Undo 真逻辑、`@Terminals` 等无数据源类型。
- 不作 `next build`。
- **作废**：顶部技能芯片条；整框替换为单一 `/skill:`。

## 约束

- 复用现有 `/` 面板与 `@` 菜单，只改触发位置与插入范围。
- `ChatInput.test.mjs` 中模型/工具预设断言保持。
