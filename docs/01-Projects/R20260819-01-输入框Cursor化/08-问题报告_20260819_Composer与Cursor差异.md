## 问题报告（PR-02）

| 字段 | 值 |
|------|----|
| 问题描述 | 空闲发送钮箭头向右（→），Cursor 为向上（↑） |
| 发现场景 | 对照 Cursor 深色 Composer 与本仓浅色输入框右下角 |
| 根因分析 | 发送 SVG 画的是水平线 + 朝右折线，不是垂直向上 |
| 严重程度 | P1 |
| 状态 | 方案待确认 |
| 关联 WP | 建议 WP-A（图标与主按钮态） |

### 现象

本仓空闲主按钮：圆形底 + **向右箭头**。Cursor：圆形底 + **向上箭头**。用户明确「图标方向搞错了」。

### 根因

`ChatInput.tsx` 空闲发送图标（约 2269–2271 行）：

- `line x1="2" y1="7" x2="11" y2="7"`（水平）
- `polyline points="7.5 3 12 7 7.5 11"`（箭头朝右）

这是「提交到下一列」的阅读方向，不是 Composer「把内容送进上方对话流」的方向。Cursor 用向上，和对话列表在输入框 **上方** 的空间模型一致。

流式时框内出现的 follow-up 图标反而带「向上」折线，和空闲发送方向不一致，加重错乱。

### 方案选项

- **选项 A**：空闲主按钮改为向上箭头；尺寸/描边与现圆钮一致。（**推荐**）
- **选项 B**：保持向右，只改文案说明。缺点：与用户要求和 Cursor 对照冲突。

### @待确认

- [ ] 确认选项 A（仅改方向，不改圆形容器）

## 问题报告（PR-03）

| 字段 | 值 |
|------|----|
| 问题描述 | 模型名在框外左侧，思考深度在框外右侧，未按 Cursor 成组 |
| 发现场景 | 本仓底栏：左「DeepSeek V4 Flash」，右「high / default / 压缩」 |
| 根因分析 | 底行被做成 `LEFT 模型 | spacer | RIGHT 思考+工具+压缩`，与 Cursor「左簇：模式胶囊 + 思考/速度文案」不是同一信息架构 |
| 严重程度 | P0 |
| 状态 | 方案待确认 |
| 关联 WP | 建议 WP-B（模型×思考成组） |

### 现象

Cursor：

```text
[∞ Agent ▾]   Medium Fast ▾     ……     附件  发送
```

「Medium Fast」是 **思考档 + 速度选项** 的摘要触发器；模型在该菜单的 Model 段进入二级。

本仓：

```text
框内：圆环 附件 语音 发送
框外： [芯片图标 模型名]     ……     [灯泡 high] [扳手 default] [压缩]
```

模型与思考 **既不在同一视觉组，也不在同一菜单**。用户要求「严格按照 Cursor 的输入框来」。

### 根因

产品层：R-01 第一轮只做技能/圆环；R-13 又把「模型/思考留在 Composer」写成冻结，**没有规定成组方式**。  
实现层：`ChatInput.tsx` 约 2296–2472 行左簇只放模型；2552–2638 行思考独立下拉，中间 `flex: 1` 撑开。

本仓没有 Agent/Ask，也没有 Cursor「Fast」开关。若把「默认」（工具预设）误当成 Fast 塞进同一颗「Medium Fast」按钮，会教错用户。

### 方案选项

- **选项 A（推荐）**：左侧 **一组**——思考摘要文案（如 `high`）作主触发；菜单内分节：思考档位、工具预设（本仓 Options）、模型（进入现有模型列表）。视觉上紧挨，可带轻量分隔，不做成两颗远距离按钮。
- **选项 B**：两颗按钮紧挨（思考摘要 + 模型名省略），共用一个弹出层锚点。更接近「两个 trigger」，菜单仍一套。
- **选项 C**：只把两颗按钮并排，菜单仍完全独立。贴近「放一起」，但不是 Cursor 的一套菜单。

### @待确认

- [ ] 确认 A / B / C
- [ ] 摘要文案用思考档（`high`）还是「思考 + 模型短名」拼一行

| 问题描述 | **压缩**仍在输入框圆角矩形外面（模型×思考也应进框；喇叭/工具另见 PR-08） |

## 问题报告（PR-05）

| 字段 | 值 |
|------|----|
| 问题描述 | 对话变窄时，框内控件不会按「从左到右」隐藏；圆环有数据就一直占位 |
| 发现场景 | 用户说明 + `ContextUsageRing` `flexShrink: 0` |
| 根因分析 | 无 ResizeObserver / 容器查询优先级；圆环与模型名都是不收缩或只截字 |
| 严重程度 | P1 |
| 状态 | 方案待确认 |
| 关联 WP | 建议 WP-D（溢出隐藏） |

### 现象

用户期望：列变窄 → 同一排功能 **从左往右一个个没**；并举例 **上下文圆环会藏掉**。

现状：

- 圆环：`flexShrink: 0`，有 `contextWindow` 就渲染，从不因宽度卸载。
- 模型按钮：`maxWidth: 220` + 省略号，是 **截字** 不是隐藏整控件。
- 桌面右簇：思考/压缩等始终整排；窄了会挤爆，没有优先级卸载。
- 移动端：用「更多控件」 overlays，不是桌面那种逐步隐藏。

### 根因

没有「铬条可用宽度 → 按优先级 `display:none` / 不挂载」的策略。隐藏顺序未产品化。

### 方案选项

推荐默认卸载顺序（**先藏 = 最先牺牲**），与「从左到右」+「圆环先没」同时满足：

1. 上下文圆环（用户点名）
2. 语音灰按钮（无真能力）
3. 压缩（先去文字留图标，再整颗卸；`/compact` 仍可用）
4. 左簇文案缩短（只留图标或思考短标签）
5. **永不隐藏**：发送 / 停止主按钮；附件尽量保留
6. **不在此列**：喇叭、工具预设（窗口底栏，不随对话列变窄卸载）

「从左到右」落实为：左簇先缩字，再卸左簇里的次要段；右簇按上表从圆环开始卸。发送钉在最右。

### @待确认

- [ ] 确认上述卸载顺序，或改成严格「几何上从左到右摘控件」
- [ ] 藏掉的能力是否进「⋯」溢出菜单（Cursor 常见）还是直接不可见（键盘仍可用的除外）

## 问题报告（PR-06）

| 字段 | 值 |
|------|----|
| 问题描述 | 模型返回过程中，停止不是「发送圆钮里的方块」 |
| 发现场景 | 用户要求；代码分流式与空闲为两套 UI |
| 根因分析 | `isStreaming` 时主圆钮被 steer/follow-up 替换；停止在框外独立红钮 |
| 严重程度 | P0 |
| 状态 | 方案待确认 |
| 关联 WP | 建议 WP-A |

### 现象

| 状态 | Cursor | 本仓 |
|------|--------|------|
| 空闲 | 圆钮 + 上箭头 | 圆钮 + 右箭头 |
| 生成中 | **同一圆钮** 中心方块 = 停止 | 框内：打断/排队；框外：红框「Stop」+ 方块图标 |

用户盯的是 **主发送位的态机**，不是另起一条停止工具。

### 根因

约 2198–2273 行：`isStreaming ? (steer + followup) : (send)`。  
约 2766–2790 行：流式时框外再画 Stop（方块 + `t("chat.stop")`）。

方块语义用对了，**位置用错了**。压缩进行中按钮里也有方块（约 2754 行），和「发送位停止」是两件事，不能合并成一颗按钮。

### 方案选项

- **选项 A（推荐）**：主圆钮三态——空闲禁用上箭头 / 空闲可发上箭头 / 流式方块停止。框外 Stop 删除。
- **选项 B**：主圆钮变方块停止，steer/follow-up 缩成主钮左侧次要图标。
- **选项 C**：维持框外 Stop，只改发送箭头。不满足用户 4。

### @待确认

- [ ] 确认 A 或 B（steer/follow-up 去留）

| 字段 | 值 |
|------|----|
| 问题描述 | 流式时思考、压缩整段 `!isStreaming &&` 卸掉，铬条能力面突变 |

### 方案选项

- **选项 A（推荐）**：流式时左簇保留、禁用；右簇主钮变停止。与 PR-06-A 绑定。
- **选项 B**：流式继续隐藏设置，只改主钮。设置会「闪没」。
