# 分析报告：上下文圆环时隐时现

| 属性 | 值 |
|------|----|
| 日期 | 2026-08-19 |
| R 主题 | [R20260819-01-输入框Cursor化](./00-README.md) |
| 模式 | PM-51a（记录→调查→方案，**确认后再修**） |
| 状态 | 根因已落档；未改行为 |

用户原话：圆环有时出现、有时隐藏，感觉莫名其妙。要求查清根本原因并记录。

---

## 1. 表层现象

同一块 Composer 右下角的上下文圆环：

- 有的会话有，有的没有；
- 新开对话常常没有，回过一轮又有；
- 对话列几乎没动，圆环却会丢；
- 把对话列拉宽一点又回来。

没有单独的「显示圆环」开关，所以像随机故障。

---

## 2. 直接原因（代码，两条独立门闩）

圆环能不能出现，要同时通过 **数据** 和 **宽度**。两条门闩互不通信，任一失败就整颗 `null`。

### 2.1 数据门闩（上一轮已拆渲染条件，数据源仍会空）

| 点 | 位置 | 说明 |
|----|------|------|
| 初值永远是 `null` | `hooks/useAgentSession.ts` `useState(null)` | 新会话、尚无 wrapper、`get_state` 还没回来，都是 `null` |
| SDK 可空 | `lib/rpc-manager.ts` `get_state` | `this.inner.getContextUsage()` 为 `undefined` 时写成 `contextUsage: null` |
| 写入是「有字段才改」 | `useAgentSession` 多处 `if (state.contextUsage !== undefined)` | 没跑过一轮、wrapper 已毁、只读打开历史会话，前端一直停在 `null` |
| **旧渲染条件** | `ChatInput.tsx`（上一轮之前） | `chromeVis.showRing && contextUsage?.contextWindow` —— 没有窗口数字就 **不挂载** |

上一轮（[11-改善](./11-改善_20260819_铬条密度圆环与停止方块.md)）已改成「有 `showRing` 就挂载」，不再要求 `contextWindow`。  
**数据为空时圆环仍可能「看起来没有」**，见 §2.3。

### 2.2 宽度门闩（现在还在，而且测的是铬条行）

| 点 | 位置 | 说明 |
|----|------|------|
| 状态初值 | `ChatInput.tsx` `chromeWidth = 9999` | 首帧当作极宽 → 先画圆环 |
| 测量对象 | 同一文件 `ResizeObserver` 看 `chromeRowRef` | 测的是 **铬条这一行的 `contentRect.width`**，不是对话列、也不是 Composer 外框 |
| 判定 | `lib/composer-chrome.ts` | `showRing = width >= 阈值` |
| 旧阈值 | 曾为 **400** | 见下表：默认对话列会踩空 |
| 现阈值 | **220** | 默认列能过；拖到接近收起仍会藏 |

铬条行实际宽度 ≈ 对话列宽 − Composer 左右垫 16×2 − 卡片左右垫 10×2 − 边框 2：

```text
chromeWidth ≈ chatPanelWidth - 54
```

对话列出厂值见 `lib/panel-layout.ts`：

| 场景 | 列宽 | 估铬条宽 | 旧阈值 400 | 现阈值 220 |
|------|------|----------|------------|------------|
| 回退 / 常见 `RIGHT_PANEL_FALLBACK_WIDTH` | **380** | **326** | **藏** | 显 |
| 编辑器默认 `clamp(24vw, 360, 420)` | 360～420 | 306～366 | **多数藏** | 显 |
| 列最小 `RIGHT_PANEL_MIN_WIDTH` | 320 | 266 | 藏 | 显 |
| 列最大 560 | 560 | 506 | 显 | 显 |
| 整栏往右压到 `SNAP_COLLAPSE` 附近 | 240 | 186 | 藏 | **藏** |
| `ResizeObserver` 尚未布局或先报 0 | 0 | 0 | 藏 | 藏 |

**出厂 380 列 + 旧 400 阈值 = 圆环默认就不画。**  
用户把列拉过约 454px（400+54）圆环出现；松手回 380 又没。这不是闪烁函数，是阈值卡在默认宽度上。

`ResizeObserver` 若在布局完成前报 `0`，会先卸圆环，等下一次有效宽度再挂上 → 换会话 / 空态切对话态时闪一下。

### 2.3 空环不可见（数据门闩拆了之后的「假隐藏」）

`ContextUsageRing`：`percent === null` 当 **0%** 画。只有 `--border` 细圈，没有 `--accent` 弧。  
圆环坐在卡片 `--bg` 上，边框色本身就淡，15×15 的空圈几乎看不见。  
用量一到，彩色弧出现 —— 用户会说「圆环冒出来了」。组件其实一直在。

### 2.4 加重闪一下的卸载

`ChatWindow` 用 `isEmptyNew` 三元：**空新会话** 和 **已有消息** 是两棵子树，各渲染一次 `{chatInputElement}`。  
发出第一条后 `isEmptyNew` 变 false，`ChatInput` **整棵卸载再挂**，`chromeWidth` 回到 9999，Observer 重绑。和 §2.2 的 0 宽回调叠在一起，会闪。

---

## 3. 根本原因

圆环被设计成 **可牺牲的诊断件**（[09-方案 §4](./09-方案_20260819_Composer控件与Cursor对齐.md)：收窄时「圆环先藏」），实现上却用了两条会自己抖动的条件，又没有告诉用户「现在被藏了」。

1. **用量数据不是稳定开关。** `getContextUsage()` 随 AgentSession 生命周期出现/消失。用它决定 *mount*，圆环就会在「还没跑过 / wrapper 没起 / 只读历史」时消失。用户没改布局，只是换了会话或发了第一句。
2. **宽度阈值踩在产品默认列宽上。** 隐藏策略按「对话列变窄」写，测量却是扣完两层 padding 的铬条行；400px 大于默认 380 列扣垫后的 ~326。默认编辑器布局下圆环被系统性藏掉，只有「把列拉宽」或「全宽对话」才出现。
3. **藏的方式是卸载，不是弱化。** `null` 掉节点后，没有占位、没有「用量改去顶栏」的提示，所以像 bug。
4. **空数据仍画 0% 淡圈**（上一轮「常显」的残留），视觉上继续等于隐藏。

不是 ResizeObserver 随机坏了，也不是某一会话文件损坏。是 **产品规则（先藏圆环）× 错误阈值 × 把 SDK 空值当成「不要画」** 叠出来的确定行为。

---

## 4. 为何上一轮「常显」没有根治

[11-改善](./11-改善_20260819_铬条密度圆环与停止方块.md) 做了两件事：去掉 `contextWindow` 渲染条件；阈值 400→220。

| 仍在的问题 | 结果 |
|------------|------|
| 宽度门闩还在，测的仍是铬条行 | 列靠近 240 或 RO 报 0 仍整颗卸掉 |
| 空环仍是 0% `--border` | 无用量时肉眼常当「没有」 |
| `isEmptyNew` 仍拆两棵树 | 第一句发出后可能闪一次 |

所以用户仍觉得「有时有、有时没有」。上一轮是症状缓解，不是根治。

---

## 5. 复现（不改代码即可对）

1. **默认编辑器布局 + 旧 400 阈值（已不在主干，但是历史主因）**  
   对话列约 380 → 铬条约 326 → 圆环不出现。把列拖到 ≥ ~454 再出现。
2. **新会话、还没回过一句（数据门闩，旧代码）**  
   `contextUsage === null` → 不画。同一列宽，第一轮结束后出现。
3. **现网 220 阈值**  
   把对话列拖到接近整栏收起（~240）→ 圆环消失；拉回来又在。
4. **空环假消失**  
   有节点、无 percent：只有淡圈。有用量后彩色弧「出现」。

---

## 6. 修复方向（未施工，待确认）

推荐一次做完，避免再降阈值应付。

| 步 | 做什么 | 不做什么 |
|----|--------|----------|
| 1 | **圆环常驻**：有 Composer 就画。宽度不够时只让模型名截断，**不再 `null` 掉圆环** | 不把圆环迁底栏（R-13 D5 Token 另案） |
| 2 | 若仍要窄列卸圆环：测量 **Composer 卡片外框或对话列**，阈值必须低于 `RIGHT_PANEL_MIN_WIDTH - 54`（320−54=266，例如 200 仍会在最小列误伤）。Observer **忽略 ≤0** | 不要再观察「含圆环的铬条行」来决定圆环在不在 |
| 3 | 无 `percent` 时画可见空态（略深的轨道 +「未知」），不要 0% 淡圈冒充隐藏 | 不编造 token 数字 |
| 4 | `isEmptyNew` 两分支共用同一棵 `ChatInput`（或 `key` 稳定），避免首条消息整棵重挂 | 不为此重做空态布局 |

与 F-15「圆环优先隐藏」的冲突：F-15 是收窄时的让位；用户本轮要的是 **不要无解释地消失**。建议修订 F-15：圆环常驻，窄列只截模型名。

### 是否临时缓解

上一轮 400→220 + 去掉数据渲染条件 = **临时缓解**。本篇方案才是根治。未授权前不改代码。

---

## 7. In / Out Scope（确认后施工用）

- **In**：圆环显隐策略、测量对象、空态描边、避免空态/对话态拆树重挂。
- **Out**：Token 进底栏（R-13 D5）、圆环点击展开分类、改 `getContextUsage()` SDK。
