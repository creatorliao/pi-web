## PR-01 选完技能后光标像换了行，技能也不像胶囊

### 表层现象

1. 从 `/` 菜单选中技能后，输入区出现 **两到三行**：上方一颗带 × 的纯文本标签（如 `bailian-ai-master`），中间是原文 `/skill:bailian-ai-master`，光标落在再下一行。
2. 技能没有 Cursor 那种 **行内胶囊**（圆角胶囊底 + 另一种颜色），只是浅底矩形或芯片条里的白字。

### 直接原因（代码）

| 点 | 位置 | 说明 |
|----|------|------|
| 芯片条独占一行 | `ChatInput.tsx` 闭合 token 的 `closedComposerTokens` 渲染块 | 芯片在 **textarea 上方另起 flex 行**。选中技能后必然「上一行芯片、下一行原文」，光标在原文末尾，视觉上就是换行。 |
| 芯片样式不像胶囊 | `globals.css` `.composer-chip` / `.composer-token-skill` | 芯片条用灰底小字；行内高亮只有 `border-radius: 4px` 且 **不能加 padding**（否则和 textarea 折行错位）。截图像方块而不是胶囊。 |
| 可能多出一个真换行 | `applySlashCommand` + `handleKeyDown` | 插入值是 `` `/${command.name} ` ``，本身无 `\n`。Enter 选中后会 `preventDefault`。但菜单关闭后若 **Enter 连发**（keydown repeat），第二次会按普通 Enter 处理（桌面即发送或插入换行）。`applySlashCommand` **未写 `valueRef.current`**，与草稿/恢复路径不一致，加重错乱感。 |
| 高亮折行 | `.composer-highlight` 的 `word-break: break-word` | 长 `/skill:…` 可能在叠加层折到第二行，和光标行不一致。 |

### 根本原因

需求理解错了：把 Cursor 的 **行内胶囊** 做成了 **顶栏标签 + 透明正文**。

实现上三层叠在一起：

1. 顶栏芯片（假胶囊，Cursor 没有这个位置）
2. `ComposerHighlight` 着色副本
3. `color: transparent` 的 textarea——**光标、选区、蓝底都在这里**，所以看见「底部透明技能」

透明叠加架构 **无法**让光标住在胶囊节点里，只会住在幽灵字里。

### 修复方向（推荐）

**取消技能/斜杠的独立芯片条**，只在叠加层做 **行内胶囊**；`@` 可同样行内圆角（圆点用 CSS `::before` 零宽方案会错位，改为胶囊左侧用背景色区分即可）。

行内胶囊且不撑歪折行：

- 叠加层 token：`border-radius: 999px`、`box-decoration-break: clone`、**不加左右 padding**。
- 用 `box-shadow: 0 0 0 3px <胶囊底色>` 做出「包住文字」的厚度，阴影不占 layout，和 textarea 字宽一致。
- 技能用 `--accent` 浅底 + accent 字；`@` 用 `--user-bg`；其它 `/` 用 `--bg-subtle`。
- `applySlashCommand`：写入 `valueRef`；rAF 里改用 `applyComposerFieldHeight`；选中后 **吞掉紧随的 Enter keyup/keydown**（`slashJustAppliedRef`，约 200ms），防止连发换行。
- 叠加层对 token 使用 `overflow-wrap: normal; word-break: keep-all`，避免无空格的 `/skill:…` 被从中间掰开。

芯片条的 × 删除：改为 **Backspace 在 token 末尾一次删整段**（解析 `parseClosedComposerTokens`，caret 紧贴 token 后则删 `[start,end]`）。不恢复独立芯片条。

### 是否临时缓解

否。按上行改是根治，不是先藏芯片条再说。

## PR-02 悬停右下角圆环没有好看的用量提示

### 表层现象

鼠标停在上下文圆环上，期望看到「当前用了多少」的体面提示；现在几乎没有，或只有浏览器原生 `title`（延迟长、样式丑、不好看用量）。

### 直接原因

`ContextUsageRing` 只用 `title={title}`。原生 tooltip：

- 出现慢，小圆环容易划走就没了；
- 不能排版（百分比、已用 token、窗口大小分行）；
- 深/浅色主题无法对齐 `--bg-panel`。

`contextUsage` 已有 `percent` / `tokens` / `contextWindow`，数据够，是展示层没做。

### 根本原因

上一轮把圆环做成「有就行」，把明细让给顶栏，悬停体验没按 Composer 做。

### 修复方向

自绘悬停浮层（不用 `title`）：

- 圆环 `position: relative`；悬停/焦点时在 **上方** 出卡片（`var(--bg)` + `var(--border)` + 小阴影，圆角 8～10，字号 12）。
- 第一行：**上下文占用** + 大号 `NN%`（无 percent 则「未知」）。
- 第二行：`已用 {tokens} / 窗口 {contextWindow}`（tokens 为空则只显示窗口）。
- `pointer-events` 覆盖圆环 28×28，可稍扩 hit 区；`z-index` 高于输入框工具条。
- `aria-label` 保留完整句子，供读屏。

### 是否临时缓解

否。

## 方案实施步骤（确认后施工，3～5 步）

1. 去掉技能/命令独立芯片条；保留行内高亮，按胶囊 CSS（box-shadow 扩边 + `999px`）。
2. `applySlashCommand` 同步 `valueRef` + 短时吞 Enter；高亮 token 禁止无空格硬折行。
3. `ContextUsageRing` 改为自绘 hover 卡片，接 `percent/tokens/contextWindow`。
4. 单测：`applySlashCommand` 插入不含 `\n`；token 样式类名存在。手验：选技能后光标在同一行胶囊后。
5. i18n：圆环卡片中英文字。
