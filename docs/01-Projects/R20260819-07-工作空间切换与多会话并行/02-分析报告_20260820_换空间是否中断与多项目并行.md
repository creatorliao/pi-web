本篇只回答三句：

1. 模型还在跑时点「切换工作空间」，原来那条会不会断？
2. 现在能不能一次跑多个项目？
3. 若将来做成「一个浏览器页签对应一个项目」，现有实现差在哪？

---

## 1. 答复（给决策用）

| 问题 | 答复 |
|------|------|
| 换工作空间会不会把正在跑的 Agent 掐掉？ | **不会。** 换的是界面上的「当前项目 / 当前对话」。服务端那条 `AgentSession` 留在 Node 进程里继续 `prompt()`。中止只发生在人点停止 / Esc 发 `abort`，或改项目信任时按 cwd 拆包装器。 |
| 现在算不算支持多项目同时执行？ | **运行时算，界面不算并排。** 同一 pi-web 进程里可以同时有多条会话在跑，cwd 可以属于不同项目。浏览器**一个页签只渲染一个 `ChatWindow`**。切到项目 B 后，项目 A 的会话在侧栏标「运行中」，跑完可提示音 / 通知。 |
| 「一个页签 = 一个项目」现在有吗？ | **没有。** 现在是「一个页签 = 一整台 pi-web 壳」，壳里再切项目。多项目并行靠**进程内多会话**，不是多页签隔离，也不是多个 `pi` 进程。 |

一句话给用户：**切换工作空间只是换你看着的那一扇窗，不会把后台那条模型跑停掉；多个项目可以同时在后台跑，只是你一次只能盯着其中一个对话。**

---

## 2. 现行架构（和「断不断」有关的层）

```text
浏览器一个页签
  └─ 一个 AppShell
       └─ 一个 ChatWindow（key=sessionKey，换项目会卸掉重挂）
            └─ SSE：只订阅「当前这条」sessionId
                 │  卸载时 close EventSource，不发 abort
服务端同一个 Next.js 进程
  └─ globalThis.__piSessions : Map<sessionId, AgentSessionWrapper>
       ├─ 会话 A（cwd=项目甲）  ← 可 isRunning
       ├─ 会话 B（cwd=项目乙）  ← 可 isRunning
       └─ … 无「全局只准一个 Agent」锁
```

内核不在独立 `pi` 子进程里，见领域笔记 `docs/02-Areas/20260819-01-pi-web与本机pi内核关系.md`。

---

## 3. 换工作空间时代码实际做了什么

入口（欢迎卡 / 模态）走到 `enterWorkspace` → `handleCwdChange`（`AppShell.tsx`）。

**会做的（界面）：**

- 关掉选择器，相位保持 `ready`。
- 若项目 identity 变了：清空上一棵树的文件页签；`setSelectedSession(null)`；`sessionKey + 1`（**拆掉当前 ChatWindow**）；按 `pi-web:last-open-by-workspace` 恢复目标项目上次打开的会话，没有则空对话。
- 同一项目内换 worktree：不拆会话、不清文件页签。

**不会做的（内核）：**

- 没有对旧 `sessionId` 调用 `POST /api/agent/[id]` 的 `abort`。
- 没有调用 `destroyRpcSessionsForCwd(旧cwd)`。
- `useAgentSession` 卸载只 `closeEvents()`（关本页 SSE）+ 清草稿定时器，**不** `sendAgentCommand(..., { type: "abort" })`。

SSE 断开只取消浏览器订阅（`lib/agent-event-stream.ts` 的 `cleanup` 卸监听、关流）。Agent 主循环在包装器里，不绑在这条 HTTP 连接上。再点回该会话：若仍在流式，会重连 SSE 接上（`GET /api/agent/[id]` 见 `isStreaming` 则自动连）。

侧栏继续每 2.5s（页可见）拉 `/api/agent/running`；`getRunningRpcSessionIds()` 扫整张 Map，所以**别的项目里还在跑的 id 仍会亮**。

## 4. 什么情况下才会真的停

| 动作 | 是否停旧任务 |
|------|----------------|
| 切换工作空间 / 换项目卡片 | 否 |
| 点另一条会话、新建对话 | 否（只换眼前的 ChatWindow） |
| 同一页签里点停止 / Esc → `abort` | **是**，只停当前这条 |
| 改该 cwd 的项目信任（`/api/project-trust`） | **是**，`hasBusy` 会挡；强行重载会 `destroyRpcSessionsForCwd` |
| 包装器空闲约 10 分钟 | 销毁内存会话，**不删** `.jsonl`；若当时已跑完才回收。还在跑则 `isRunning()` 为真，不会按空闲拆 |
| 关掉整个 pi-web Node 进程 | 是，进程内所有包装器一起没 |
| 再开一个浏览器页签连同一端口 | 否；两页可以盯不同 sessionId，底层仍是同一 Map |

「同一条对话里同时开两个互不抢的主循环」：**不支持**。并行的粒度是 **sessionId**，不是「一个项目里再叠一条无名主循环」。

## 5. 「多项目同时执行」现在到哪一层

| 层 | 现状 | 和「一页签一项目」的差距 |
|----|------|--------------------------|
| 进程 | 一个 Node，多 `AgentSession` | 已是多项目 cwd 可同时跑 |
| 会话文件 | `~/.pi/agent/sessions/<encoded-cwd>/…` 按目录分 | 已隔离存储 |
| 浏览器壳 | **一个**页签、**一个**三栏、**一个** ChatWindow | 没有「页签 = 项目」的产品边界 |
| 前台注意 | 只能看一条流式输出；后台靠运行点 / 完成音 / 通知 | 不能并排看两个项目冒字 |
| 资源 | 共用 CPU、内存、同一套 API Key | 多开会抢配额，程序几乎不设并发硬顶 |
| 信任 / 扩展 | 按 cwd；某目录 busy 时不能顺利重载该目录扩展 | 多项目同时跑扩展时仍是进程内共享 |

因此：

- 问「能不能两个项目各跑一个长任务」→ **能**，在 A 发送，切到 B 再发送。
- 问「算不算多项目 IDE（每个窗口一个仓库）」→ **不算**。那是下一步产品形态，不是现在缺一条「换空间不要 abort」的 bug。

## 6. 将来「一页签一项目」的初步论证（不立项、不施工）

目标若是：页签甲只属于项目甲，页签乙只属于项目乙，两边同时看流式。

| 路线 | 含义 | 和现核的关系 | 代价 |
|------|------|--------------|------|
| **P0 维持** | 继续单壳多会话 | 零改；侧栏跨项目活动点已有 | 达不到「一页签一项目」 |
| **P1 多页签共用一服务** | 用户自己开两个浏览器页签，URL 带不同 `?session=` / `?cwd=` | **内核已支持**；要补的是：页签标题=项目名、深链稳定、避免两页抢同一 session 的输入焦点 | 最小增量；仍是一个 Node |
| **P2 单页内多 ChatWindow** | 一个壳里并排/分栏两个对话 | 注册表不用改；要改 AppShell 状态机（现在 `selectedSession` 单例、`sessionKey` 单槽） | 交互和性能都重 |
| **P3 每项目一个 Node / 一个 pi 进程** | 真隔离 | 与当前「进程内 SDK」相反 | 端口、鉴权、`~/.pi` 争用；除非有强隔离需求，否则过重 |

**推荐（仅论证，未拍板）：** 若只是「两个项目同时跑、偶尔并排看」，先验证 **P1**（两个浏览器页签 + 现有 running API）。现核已经按 sessionId 并行；缺的是产品约定「这个页签锁定这个项目」，不是再做一套 Agent 运行时。

P2/P3 会碰到：Composer 冻结面、底栏「我在哪」只有一条、文件允许根按会话 cwd 累加、同一 API Key 限流。那些是扩展时的红线，不是本轮选择器改版的 scope。

价值观对照（先记，避免以后把并行做成第二套列表）：

- **好上手**：VS Code 是多窗口/多文件夹；Cursor 也是窗口级项目。人对齐的是「再开一个窗口」，不是「一个弹层里同时跑两个内核」。
- **不加戏**：不要为「看起来像并行」在欢迎卡上画双会话预览；后台跑 + 侧栏运行点已经闭环。

## 7. 依据（2026-08-20 复核）

| 材料 | 证明什么 |
|------|----------|
| `AppShell.enterWorkspace` / `handleCwdChange` | 换项目只改壳状态、remount ChatWindow，不 abort |
