## 1. 结论先说

| 疑问 | 结论 |
|------|------|
| 怎么换工作空间 | 界面里它叫**项目**，本质是换会话的工作目录（`cwd`）。左侧栏顶部选项目、填自定义路径、用默认日目录，或点另一条会话。Git 仓库根上还可以换 worktree。 |
| 能不能并行多个「pi」 | **能并行多个会话**，但**不会**再拉起多个本机 `pi` 进程。一个 Node 服务里可以同时有多个 `AgentSession` 在跑。浏览器**一次只显示一个对话**；切走后后台会话继续跑，侧栏会标「运行中」。 |
| 当前程序能否做到「多起几个对话同时执行」 | **可以。** 先在会话 A 发送，再点「新建」或点会话 B 再发送。两侧都会进 `/api/agent/running`。同一会话内部一般仍是一轮一轮来，不能在同一条对话里叠两个互不相关的主循环。 |

> **注意：** 这里的「工作空间」不是 VS Code / Cursor 的 Workspace 文件。pi-web 用**项目（目录）+ 会话列表**表达同一件事。

## 2. 疑问一：普通用户怎么切换工作空间

### 2.1 界面上对应什么

用户要换的是：**Agent 读写文件、跑命令时所在的目录**，以及**这个目录所属项目下的会话列表**。

侧栏中文文案（`lib/i18n/messages/zh-CN.ts`）：

- 「选择项目…」：最近用过的项目下拉
- 「自定义路径…」：自己指定一个本机目录
- 「使用默认目录」：当天自动建 `~/pi-cwd-YYYYMMDD`
- 「新建」：在**当前选中目录**里开一条新会话
- 「切换 worktree」：仅 Git 仓库**根目录**出现
- 会话行上的「Agent 运行中…」：该会话后台还在跑

同一 Git 仓库的主工作区与 worktree 会归到**同一个项目**里列会话，避免换 checkout 后会话「消失」。

### 2.2 操作路径（按常见程度）

**路径 A — 从最近项目里选（最常用）**

1. 打开左侧栏顶部的项目选择器。
2. 点一个已有项目。列表只显示该项目（含其 worktree）下的会话。
3. 点一条会话进入对话；或点「新建」在当前目录开空会话。
4. 换到另一个项目时，浏览器会尽量**恢复你上次在该项目打开的会话**（`localStorage` 键 `pi-web:last-open-by-workspace`）。

**路径 B — 打开一个列表里没有的目录**

1. 选「自定义路径…」，用目录选择器或粘贴绝对路径（也支持 `~`）。
2. 服务端 `POST /api/cwd/validate`：必须是已存在的目录。
3. 通过后该路径成为当前 `cwd`，并加入文件浏览允许根。
4. 再「新建」或等该目录下出现会话。

**路径 C — 不想绑某个代码仓库**

选「使用默认目录」。服务端 `POST /api/default-cwd` 创建并返回 `~/pi-cwd-当天日期`，适合临时问事、不污染某个仓库。

**路径 D — 点另一条会话**

点会话会把当前目录改成**那条会话自己的 `cwd`**。同一项目里若会话开在不同 worktree，等于顺带换了 checkout。

**路径 E — 同一仓库换分支工作区**

当前目录是 Git **顶层**时，出现 worktree 开关：切到已有 worktree，或「新建 worktree」按分支 checkout（目录在 `<仓库>-worktrees/<分支>`）。新会话会落在该 worktree 路径上。子目录里开关会藏起来，需先「打开仓库根目录」。

**路径 F — 地址栏（进阶）**

- `/?session=<会话id>`：打开指定会话（并带上它的目录）。
- 启动时若带了 cwd 查询参数，会先走 validate，再进入该目录。

### 2.3 换项目时界面会怎样

- **换到另一个项目**：文件页签清空（路径属于上一棵树）。
- **同一项目内换 worktree**：文件页签可保留。
- 中间主区始终只有**一个** `ChatWindow`；换会话会重挂载聊天（`sessionKey`），不是左右并排两个对话。

### 2.4 和「本机再开一个 pi」的关系

换项目、换会话**都不会**新开一个 `pi` 可执行文件。只是下一条消息用哪个 `cwd`、读哪份 `.jsonl`。内核关系见 `docs/02-Areas/20260819-01-pi-web与本机pi内核关系.md`。

## 3. 疑问二：能不能并行执行多个对话

### 3.1 用户能做什么

**支持的用法：**

1. 在会话 A 发送一条会跑很久的任务。
2. 侧栏再「新建」，或点会话 B（可以是另一项目）。
3. 在 B 再发送。A **不会因为你切走而被中止**。
4. 侧栏对仍在跑的会话显示运行标记；别的项目有运行/未读时，收起的项目按钮上也会有活动提示。
5. 后台会话跑完：标未读、可响完成音（`onBackgroundTaskDone`），也可走浏览器通知点回该会话。

**不支持或不要指望的用法：**

| 期望 | 实际 |
|------|------|
| 屏幕上并排两个聊天同时看字往外冒 | 没有分屏双对话；一次只渲染一个 `ChatWindow` |
| 同一条对话里同时跑两个互不抢的主 Agent | 同一 `sessionId` 一轮主循环；可用排队 / 跟进，不是两条独立内核 |
| 每开一个对话就多一个名为 `pi` 的系统进程 | 都在**同一个** Next.js Node 进程里，注册表是 `globalThis.__piSessions` |
| 无限并行且互不影响额度 | 共用本机 CPU/内存和模型供应商配额；程序几乎不设「最多同时 N 个」硬顶 |

### 3.2 当前程序为何能并行

服务端按**会话 id** 建包装器，锁也按 id，没有「全局只准跑一个 Agent」：

```text
POST /api/agent/new     → 新 id 的 AgentSession（发第一条时才真正起来）
POST /api/agent/[id]    → 对该会话 prompt / abort / …
GET  /api/agent/running → 返回所有 isRunning() 的 id
```

`getRunningRpcSessionIds()` 遍历整张 Map，说明产品按「多个 running」设计。侧栏每 2.5 秒（页签可见时）拉这个接口。

切走当前聊天时，`useAgentSession` 卸载会**关掉本页的 SSE**，但**不会**对服务端发 `abort`。包装器留在进程里继续 `prompt()`。再点回该会话，若仍在流式，会重连 SSE 并接上。

同一目录可以有多条会话同时跑。`hasBusyRpcSessionForCwd` 只用来挡「该目录正在跑时改项目信任并拆掉包装器」，不是禁止第二会话。

### 3.3 和「并行多个 pi」一句话对齐

- **问：能不能并行多个 pi？** 若指多个 CLI 进程：**当前 Web 不会这么干。**
- **问：能不能多个对话同时干活？** **能，而且界面已经按这个做了标记和完成提醒。**
- **问：算不算实现了？** **算。** 实现形态是进程内多会话，不是多进程。

### 3.4 并行时的限制（避免误以为无限）

1. **空闲回收：** 某会话停跑约 10 分钟后，包装器可能销毁；下次再发会从文件重新加载（不删会话文件）。
2. **模型与账号：** 多路同时打同一 API Key，可能限流或账单叠加。
3. **机器：** 多路 bash/编译会抢本机资源；它们是工具在会话 `cwd` 下执行，仍不是多个 `pi`。
4. **信任变更：** 某 `cwd` 上有正在跑的会话时，不能顺利重载该目录的项目扩展。
5. **两个浏览器页签：** 都连同一 pi-web 时，可以分别盯不同会话；底层仍是同一进程里的多包装器。

## 4. 给普通用户的最短操作单

**换一个代码目录工作**

1. 左侧「选择项目…」→ 已有项目，或「自定义路径…」选文件夹。  
2. 点会话，或「新建」后发第一条。

**同时跑两件事**

1. 会话 A 发送。  
2. 「新建」或点会话 B，再发送。  
3. 看侧栏运行点；做完再点回去看结果。不必、也无法为每个对话再开一个本机 `pi`。
