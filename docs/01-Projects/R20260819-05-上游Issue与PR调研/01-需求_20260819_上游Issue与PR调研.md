## 目标（Why + What）

- **业务目标**：把本仓做成**面向普通用户**的智能体桌面/网页工具：功能够用、界面简洁大方、体验符合大多数人习惯，尽量压低安装、配置、理解成本。
- **本轮交付（已完成）**：对照 `agegr/pi-web` 的 Issue / PR，产出问题报告、PR 报告、低垂果实与综合方案。
- **下一阶段成功（待确认后施工）**：普通人用当前浏览器打开本机地址就能聊；不改已有布局与输入框；不为「完善」往设置里堆习惯开关。
- **用户价值**：先避开会「打不开、发不出去、停不下来、钱被刷、界面崩」的坑；再从社区已写好的 PR 里挑能降低门槛的能力，避免闭门造车。
- **成功标准**：
  - 致命问题有分级、有链接、有「对我们普通用户是否要命」的判断。
  - PR 有「值得整合 / 可观察 / 暂缓」三类，对齐简洁与低门槛，而不是功能堆叠。

## 非功能需求

- **证据**：结论必须带上游编号与 URL，禁止口头「社区好像有这个问题」。
- **取样透明**：写明 `gh` 窗口（最近 200 Issue / 200 PR），避免假装穷尽全库。
- **中立**：已关闭不等于「我们不用管」——已修的要标「上游已关，本仓需核对是否已带上」。
