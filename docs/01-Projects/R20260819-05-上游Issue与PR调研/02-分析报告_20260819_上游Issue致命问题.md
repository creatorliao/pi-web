# 分析报告：上游 Issue 中的致命与高影响问题

| 属性 | 值 |
|------|----|
| 日期 | 2026-08-19 |
| 上游 | [agegr/pi-web](https://github.com/agegr/pi-web) |
| 取样 | `gh issue list --state all --limit 200` → OPEN 37 / CLOSED 163；Issue **无标签**，分级由本报告按对普通用户的伤害判定 |
| 产品镜头 | 打得开、发得出、停得住、不乱扣费、不崩、不难用 |

## 结论先行

对「普通用户用得舒服」杀伤最大的，不是缺终端、缺繁体中文，而是这四类：

1. **整页不可用**：Chromium 新版本把所有 API 打成 403，侧边栏空、模型配不了。
2. **会话卡死 / 资源泄漏**：Stop 按了像没按；扩展子进程堆内存，用一天电脑变卡。
3. **钱与密钥**：切走 DeepSeek 后仍可能静默打官方 Key（已关 Issue，必须核对本仓）。
4. **长对话与刷新**：四百条消息刷新约一分钟——日常用户会以为「坏了」。

其余多为体验债（回车习惯、主题对比度、文件预览上限），应进路线图但不要压过上面四类。

## P0 · 致命：用户会觉得「这软件坏了」或「不安全」

### PR-01 · Chromium 150+ 全站 403

| 字段 | 值 |
|------|----|
| 上游 | [#542](https://github.com/agegr/pi-web/issues/542) OPEN；补丁 PR [#544](https://github.com/agegr/pi-web/pull/544) / [#496](https://github.com/agegr/pi-web/pull/496) 叙事交叉 |
| 严重程度 | **P0** |
| 状态 | 上游未合；本仓须自测 Chrome/Edge 是否已踩中 |
| 发现场景 | 默认 `http://127.0.0.1:30141`，新 Chromium 把 Origin 写成不带端口的 `http://127.0.0.1`，`lib/request-security.ts` 严格比对失败 |

**现象**：打开 UI 后所有 `/api/*` 403，会话列表空，配置打不开。  
**对普通用户**：零门槛失败——装完第一次打开就废。  
**建议**：核对本仓 `isApiRequestOriginAllowed`；若仍比完整 Origin（含端口），按「比 hostname+Host、同时看 `Sec-Fetch-Site`」修，并加回归测试。**不要为了好用而关掉 CSRF 护栏。**

### PR-02 · 代理改写 Origin 协议 → POST 全 403

| 字段 | 值 |
|------|----|
| 上游 | [#497](https://github.com/agegr/pi-web/issues/497) OPEN；相关 [#511](https://github.com/agegr/pi-web/pull/511) |
| 严重程度 | **P0**（远程/隧道用户）；本机直连为 P2 |
| 状态 | 调查中 |

**现象**：Azure Dev Tunnel / 同类中继把 `x-forwarded-proto: https` 与 `Origin: http://...` 拆开，GET 能看历史、**一发消息就 403**。  
**对普通用户**：教程里「用隧道给手机用」会直接劝退。  
**建议**：若产品二期要远程，跟 #542 一并改「比 Host 不比 scheme」；一期只本机则可降优先级。

### PR-03 · Stop 死按钮 + 会话永远 running

| 字段 | 值 |
|------|----|
| 上游 | [#368](https://github.com/agegr/pi-web/issues/368) OPEN |
| 严重程度 | **P0** |
| 状态 | 与 pi 内核 abort 竞态相关（见文内 earendil-works/pi#7053） |

**现象**：工具还在跑时点停止，模型请求已 abort，但 UI 仍 running，新消息发不出去；等到工具自己的 timeout（可数分钟甚至无限）。  
**对普通用户**：最像「卡死」。大众产品必须「停止就是停止」。  
**建议**：本仓复现 bash/长工具；UI 层对「abort 已发出但 isStreaming 仍真」做超时兜底与可点的强制释放（内核修是正路，产品层要有逃生门）。

### PR-04 · 扩展子进程泄漏（dispose 不发 session_shutdown）

| 字段 | 值 |
|------|----|
| 上游 | [#546](https://github.com/agegr/pi-web/issues/546) OPEN |
| 严重程度 | **P0**（装了 MCP/context-mode 的日用机） |
| 状态 | #331 已 dispose，但不够 |

**现象**：每个会话拉起的扩展子进程（报告称约 80–160MB）不回收，一天堆到近 1GB，桌面变卡。卡在 #368 时 idle 关不掉 wrapper，泄漏更狠。  
**对普通用户**：用一会儿「电脑风扇转、网页越来越慢」，会被归因为产品劣质。  
**建议**：跟踪内核 `dispose()` 是否补 `session_shutdown`；本仓 idle/`shutdown` 路径不要只依赖「未 running」。

### PR-05 · 空 aborted 当取消、白泡不重试

| 字段 | 值 |
|------|----|
| 上游 | [#351](https://github.com/agegr/pi-web/issues/351) OPEN |
| 严重程度 | **P0**（部分模型首条消息失败率极高） |

**现象**：Provider 在 `AbortSignal=false` 时仍报 `aborted`、空内容；pi 不重试 `aborted`，于是落一条空白助手消息。报告称 6 个新会话里 5 个首次如此。  
**对普通用户**：点发送没字，以为没网或坏了。  
**建议**：本仓对「零内容 + 未用户取消」做有限次重试；同时盯内核分类。

### PR-06 · 误用官方 DeepSeek Key 静默扣费（已关，必须核对）

| 字段 | 值 |
|------|----|
| 上游 | [#486](https://github.com/agegr/pi-web/issues/486) **CLOSED** |
| 严重程度 | **P0（资金/信任）** |
| 状态 | 上游已关；本仓必须确认补丁在树 |

**现象**：用户已改供应商，进程仍可能读到环境变量 `DEEPSEEK_API_KEY` 打官方接口，余额被刮。  
**对普通用户**：比界面丑致命——一次就卸载且不信任 AI 工具。  
**建议**：查 changelog / `lib` 鉴权路径；设置页明确「当前实际打的是哪家」；禁止静默回落环境变量。

## P1 · 高影响：能用但经常难受、或破坏工作流

### PR-07 · 启动器把信号退出当成 0 / 杀父留子

| 字段 | 值 |
|------|----|
| 上游 | [#506](https://github.com/agegr/pi-web/issues/506) OPEN；[#495](https://github.com/agegr/pi-web/issues/495) CLOSED；补丁向 [#515](https://github.com/agegr/pi-web/pull/515) |
| 严重程度 | P1 |

**现象**：wrapper 丢掉 child `signal`，`code ?? 0` 把被杀当成成功；只杀父 PID 则 Next 子进程占着 30141。  
**对普通用户**：「关掉了但端口还在、再开起不来」。  
**建议**：核对本仓 `bin/pi-web.js` 进程组与退出码。

### PR-08 · 工具子进程继承 PORT / NODE_ENV

| 字段 | 值 |
|------|----|
| 上游 | [#484](https://github.com/agegr/pi-web/issues/484) CLOSED |
| 严重程度 | P1 |

**现象**：agent 里跑 `vite` / `npm install` 吃到 Next 的 `PORT=30141`、`NODE_ENV=production`，装不全依赖、端口撞车。  
**对普通用户**：让 AI「帮我启动项目」第一课就失败。  
**建议**：核对本仓是否已剥离工具环境；未剥离则进必做修复。

### PR-09 · 长会话加载极慢 / 全目录扫描

| 字段 | 值 |
|------|----|
| 上游 | [#500](https://github.com/agegr/pi-web/issues/500)、[#513](https://github.com/agegr/pi-web/issues/513) OPEN；PR [#516](https://github.com/agegr/pi-web/pull/516)、[#526](https://github.com/agegr/pi-web/pull/526) |
| 严重程度 | P1 |

**现象**：400+ 条刷新约 1 分钟；冷启动列表/打开会话扫全部 jsonl。  
**对普通用户**：历史稍长就「转圈」，大众产品不可接受。  
**建议**：优先合/移植「单会话解析、不扫目录」类补丁。

### PR-11 · 压实失败与 429 被当成额度用尽

| 字段 | 值 |
|------|----|
| 上游 | [#453](https://github.com/agegr/pi-web/issues/453) OPEN |
| 严重程度 | P1（国内百炼/阿里云用户很常见） |

**现象**：换小窗口模型压实失败；阿里云 TPM 429 正文带 `insufficient_quota`，被分类成永久欠费、不重试。  
**对普通用户**：中文用户常用 DashScope，会表现为「突然不能聊了」。  
**建议**：429 + Retry-After 一律可重试；文案区分「限流」与「欠费」。

### PR-12 · 扩展提问遮罩 / 单对话框 / iOS PWA 认证与通知
