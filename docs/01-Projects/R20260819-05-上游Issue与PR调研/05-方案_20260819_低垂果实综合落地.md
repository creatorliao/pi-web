## §0 产品北极星（回看需求，而不是回看 Issue 清单）

把几份文档里的原话收成一句，施工时用它否决「顺手再加一项」：

> **给普通人用的本机智能体：打开就能聊、界面干净、习惯跟常见软件走；程序员能力进设置，不挡路。已经做好的布局和输入框，不要为了上游 PR 再改一轮。**

| 来源 | 发展要求 | 对本方案的含义 |
|------|----------|----------------|
| 本 R 需求 | 功能完善、界面简洁大方、低门槛 | 先修「打不开 / 看不清」，不要用新开关堆「完善」 |
| R03 需求 | 主界面不像调试台；该进设置的进设置；默认编辑器三栏 | 设置页是产品资产，不是垃圾桶；布局冻结 |
| R01 / R02 | Composer 与多技能已定型 | 不重做输入条、不改展开协议 |
| 你补充 | 不做繁体；新能力走现有配置页；勿影响布局 | 红线。配置页也要克制，避免外观里塞满对话开关 |
| 你补充 | 设置里**外观不是最重要**，导航应放在最底部 | 智能体先能连上模型/技能，主题和栏位是次要修饰 |

成功标准改成**用户能感知的**，不再用「摘了几颗上游果实」：

1. 用当前 Chrome / Edge 打开本机地址，侧栏有项目、能发第一条消息（不是空列表 + HTTP 403）。
2. 编辑器布局与助手布局和现在完全一样，切设置里的布局项行为不变。
3. 设置仍是四栏；**导航顺序改为「模型 → 技能 → 插件 → 外观」**（外观沉底）。外观**页内**的主题 / 布局 / 隐藏文件 / 语言不改内容、不加「对话习惯」。
4. 普通人完成一次对话，**不必先打开设置**。第一次进设置、又没有上次分栏记忆时，默认停在 **模型**（不要再停在外观）。

## §1 体验复审：上一版方案的问题

站在「第一次用的人」和「已经习惯本仓布局的人」两边看。

### 1.1 走查记录（主路径）

| 字段 | 值 |
|------|----|
| 用户角色 | 普通用户（会用微信 / 浏览器，不懂 Origin、jsonl） |
| 目标 | 打开工具，对着自己的文件夹问一件事 |
| 起点 | 装好后浏览器打开 `http://127.0.0.1:30141` |

| 步骤 | 操作 | 期望 | 上一版方案覆盖 | 痛点 | 优先级 |
|------|------|------|----------------|------|--------|
| 1 | 打开页面 | 看到项目和对话，能点 | A1 修 403 | 若仍失败，用户只看到空壳或 `403`，没有人话 | **P0** |
| 2 | 找到上次的对话、开始打字 | 和上次一样的三栏 | 布局冻结写了 | 若顺手改顶栏/栏宽，熟用户会觉得「又改版了」 | **P0（防护）** |
| 3 | 读助手回复、看提示 | 字能读完 | B1 换行 | 上一版还想动侧栏行高，列表会变丑 | P1 |
| 4 | 看自己贴的图 | 一张图就是一张 | B3 | 叠图像坏了 | P1 |
| 5 | 需要改习惯（回车、思考展开） | 大多数人根本不会去找 | 层 C 往外观里加「对话习惯」 | **违反「少配置」**：默认已经能用，再加一组等于教用户做作业 | P2 |
| 6 | 装插件后点状态条 | 能点、字不裁 | B2 | 插件用户才遇到，不是大众主路径 | P2 |
| 7 | 终端里打 `pi-web --help` | 极少数人 | A3 | 对「打开浏览器就能用」几乎无贡献 | P3 |

### 1.2 问题清单（产品 / UX）

| # | 问题 | 根因 | 改善 |
|---|------|------|------|
| U-01 | 把「工程好做」当成「用户要」 | 低垂清单驱动 | 主路径只留 P0/P1；P2 降为可选项 |
| U-02 | 外观页职责被稀释 | 主题+布局已经是心智负担，再塞发送键/思考展开 | **本期默认不加新设置组** |
| U-03 | 403 修了但失败态仍像程序员报错 | 只改校验，不改人话 | A1 附带一句用户能懂的失败文案（不改布局） |
| U-04 | 提示音已在输入条 | 再迁进设置是搬家，不是体验升级 | 本期不动，避免用户找不到喇叭 |
| U-05 | 「完善」被理解成功能清单 | 与「简洁」打架 | 完善 = 主路径可靠、干净，不是项数多 |

### 1.3 设置页怎么用（信息架构原则）

你已经做成「左下角一个设置、里面四栏」。这是对的。复审后定三条，避免下一波把设置做成第二块调试台：

| 分栏 | 只放 | 不放 |
|------|------|------|
| **模型（默认首页）** | 供应商与模型 | — |
| 技能 | 技能开关与安装 | 写盘修复走 API，不新控件 |
| 插件 | 包 / 扩展 | MCP 整面板以后再说，且仍进这一栏 |
| **外观（导航最底）** | 看起来怎样、栏怎么摆、语言、资源管理器显隐 | 发送键、模型、插件、会话 id |

导航顺序跟「打开设置想干什么」对齐：先让智能体能干活（模型），再补技能/插件，最后才是皮肤和栏位。外观沉底不是贬低 R03 的布局开关——布局仍然在外观页里，只是**不再占用设置的第一眼**。

**「该进设置」≠「这期必须新开一组」。** 只有当默认行为会伤害一部分人、且不能靠默认值解决时，才加开关。当前：Enter 发送已是大众习惯；思考折叠已是干净默认——**都还没到必须加开关的程度。**

## §3 修订后的一期范围（推荐）

**一句话：先让人能用、能看清；不教人去设置里改习惯。**

### 3.1 必做 · 用户能感到「没坏」

| ID | 用户语言 | 做法 | 白名单 | 红线 |
|----|----------|------|--------|------|
| A1 | 「打开是空的 / 发不了」 | Origin 与 Host 比对（含剥端口、scheme 不一致）；**失败时设置页/侧栏已有的错误条用人话**，例如「无法连接本机服务，请刷新；若刚升级浏览器仍不行请反馈」。不解释 CSRF | `lib/request-security.ts` + 测试；若现有 toast/空态已有字符串，只改文案 key | 不关护栏；不改 `AppShell` 结构 |
| B1 | 「字被切掉」 | 设置页说明文字、对话里的系统/错误提示可换行 | 对应文本节点 / CSS | **不改**栏宽、顶栏、会话列表行高 |
| B3 | 「图片叠了两张」 | 用户消息大图只渲染一次 | `MessageView` + 测试 | 不改气泡以外的壳 |
| C0 | 「设置先看到能干活的」 | 导航改为 模型 → 技能 → 插件 → 外观；无记忆默认模型；无项目时禁用项回落模型而非外观 | 仅 `SettingsDialog` 导航与默认 section | 不改外观页内部、不改主窗口布局 |

### 3.2 应做 · 用户几乎无感，但会在关键时刻保护他们

| ID | 说明 |
|----|------|
| A2 | 技能开关写坏 `false`：修 PATCH。技能页样子不变。这是「完善」里的质量，不是新功能。 |

### 3.3 不做（相对上一版明确砍掉或降级）

| 原 ID | 修订 | 理由（体验 / 产品） |
|-------|------|---------------------|
| 层 C「对话习惯」整组 | **本期不做** | 违反少配置；外观页已经有布局这项重决策。等真有人被默认习惯卡住再加 |
| 完成提示音迁设置 | **不做** | 输入条已有喇叭，搬家会让熟用户找不到 |
| A3 `--help` | **降为有余力再做**，不进本期验收 | 服务装包的人，不服务打开网页的人 |
| B2 扩展状态条 | **降为有余力** | 插件路径，不是大众主路径 |
| #525 顶栏展开 | 仍不做 | 保护上一轮顶栏与布局 |
| 繁体 / PWA / 终端 / 最大化 / 提问卡 / MCP | 仍不做 | 与北极星或冻结资产冲突 |

上一版「A1 顺带修隧道 scheme」**保留在 A1 实现里**（同一函数），但产品叙事仍是「本机打得开」。不把远程手机当本期卖点。
