| 属性 | 值 |

| 日期 | 2026-08-19 |

| 产品镜头 | 功能完善但界面克制；降低配置与学习成本；不堆程序员向面板 |

## 结论先行

社区已经把「大众智能体」缺的几块写在开放 PR 里了。按**我们的目标**（舒服、简洁、低门槛），建议只认真评估下面三档，而不是 36 条全跟。

1. **值得整合（体验主路径）**：人机问答从遮罩改成对话内卡片；会话可分组/置顶路径；发送与布局符合聊天习惯；长会话变快。
2. **值得观察、择一而从**：PWA/扫码、Web Push、语音输入、MCP 图形配置、页内改文件——每条都对，但会加设置面与安全面。
3. **暂缓或易胖**：侧栏里塞终端（#522 体量含 pty）、Windows 代理超大补丁、会话分类 1800+ 行改动——先看设计再考虑自研瘦身版。

已合并 PR 说明上游默认能力在涨（通知、数学/mermaid、侧栏拖拽、i18n、工作树）。本仓是 fork，**合入策略应是拣提交，而不是盲目 merge upstream**。

## A. 强烈建议纳入产品想象（对齐普通用户）

### 1. 内置提问卡，而不是全屏弹窗

| PR | [#510](https://github.com/agegr/pi-web/pull/510) OPEN · +956 |

## C. 暂缓或需拆瘦（与「大方简洁」容易打架）

| PR | 原因 |
|----|------|
| [#522](https://github.com/agegr/pi-web/pull/522) +1440 | 标题写分隔条，diff 里已出现 `pty` / `TerminalPanel`——这是「侧栏加终端」。#507 要终端，但一期壳层加终端会把产品从「聊天智能体」拉成「迷你 IDE」。**若只需要拖分隔，应只要那几十行，不要整包终端。** |
| [#466](https://github.com/agegr/pi-web/pull/466) +1334 | Windows 代理 + 本地文件链接 + 构建扫描修复捆在一起，难审。代理对公司网有用，应拆成「设置里一项」而不是大补丁盲合。 |
| [#458](https://github.com/agegr/pi-web/pull/458) +1873 | 任意深度分类对普通用户过重；存储另开 json 方向对，实现宜瘦。 |
