## §1 设计判断（为什么现在别扭）

对照 Cursor 深色 Agents 窗，pi-web 现在缺的不是「再多一个按钮」，而是 **三块 chrome 说了三种话**：

| 区域 | 现在 | 人的预期 | 落差 |
|------|------|----------|------|
| 对话顶栏 | 空轨 + 右贴 `+` / 列表 | 「这扇对话窗」的标题和主操作 | 空，所以 `+` 像装饰不是入口 |
| 历史抽屉 | 列表顶到边，无工具 | 「这本目录」能搜、能开新页、能按天翻 | 翻历史时新建要回头找另一条轨 |
| 文件顶栏 | 「⋯ 会话」假页签 | 只放文件名 | 会话工具污染文件导航，视觉权重还压过真页签 |
| 页签下细栏 | 「磁盘文件 · 预览 · markdown」 | 这份文件在哪 | 分类标签与右侧 Source/Preview、页签后缀重复；路径藏在 tooltip |

新建不便是同一件事的行为面：

1. **入口会消失**：`+` 画在右侧 `agentWorkspace` 里。整栏一收，新建为零。主顶栏只剩「展开对话栏」，语义是显隐，不是新建。
2. **入口不好认**：空顶栏没有「新对话」标题，`+` 没有所属对象。
3. **入口不跟着任务走**：人在翻历史时，任务是「找旧的 / 开新的」，抽屉里却没有新建和搜索。
4. **快捷键藏着**：已有 `Ctrl+Alt+N`（`useGlobalKeyboardShortcuts`），界面不提示，等于没有。

不协调是同一件事的视觉面：假页签、空标题栏、无分组的长列表，三种密度撞在一起。

## §2 一条补充铁律

**06-方案：顶栏只导航，文件名只出现一次。**  
**本篇：对话是一扇窗，历史是一本目录，页签只放文件名，细栏只放路径。**

| 列 | 只允许的 chrome | 禁止 |
|----|-----------------|------|
| 中间文件顶栏 | 左栏开关 + **文件页签** + 收紧右侧（栏关着时多一枚 `+`） | 「会话」字、会话下拉、把对话标题写到这里 |
| 页签下细栏 | 左侧**相对路径**；右侧仍是绿点 / Source·Preview / `@` / 下载 | 「磁盘文件 / 预览 / markdown」分类词；再画一行 36px 文件名 title |
| 右侧对话顶栏 | 会话标题 + `[+] [⋯] [列表]` | 再空一条轨；把会话菜单送回页签行 |
| 历史抽屉顶 | 搜索 + 新建（可带快捷键提示） | 列表顶到边；再发明第三种 `+` 语义 |

叠层 title、假页签、历史无头、栏关后无法新建，都是这条铁律被打破。

## §5 三处新建，一种语义

同一函数：现有 `handleNewSession`（清选中、写 `newSessionCwd`、换草稿 key、必要时 `setRightPanelOpen(true)`）。

| 入口 | 何时可见 | 额外动作 |
|------|----------|----------|
| 对话顶栏 `+` | 右侧栏开着 | 无 |
| 历史「新对话」 | 历史抽屉开着 | 无（抽屉保持开，D4 不变） |
| 主顶栏 `+` | **仅**右侧整栏关着 | 先 `setRightPanelOpen(true)` 再新建 |

无 cwd 时三处都禁用，tooltip 仍用「先选项目」。已在空「新对话」上再点 `+`：保持现在的换草稿 id，避免误以为坏了。

快捷键：继续 `Ctrl+Alt+N`；历史「新对话」右侧用弱字提示，对话顶栏 `+` 的 `title` 带上快捷键。不改键位，避免和浏览器新窗 `Ctrl+N` 冲突。

## §6 对话标题栏细则

高度继续 **36px**，底边 1px `--border`，背景 `--bg-panel`（与文件顶栏齐平，这是协调的关键，不要另起一套高度）。

```text
[  会话标题（左对齐，11–12px，1 行截断）      ][ + ][ ⋯ ][ 列表 ]
```

- 标题：`selectedSession.name` → 否则首条用户消息截断 → 否则「新对话」。不在标题上再写「会话」。
- 标题不可点（本轮不做重命名）。`title` 属性给全文。
- `⋯` 打开的菜单视觉跟现在下拉一致，只是锚点改到对话顶栏右上；打开时 `⋯` 用 `--bg-selected`。
- 列表键行为不变（D1 / D2 / D4）：右抽推挤、侧栏面板图标、点开保持。
- 助手布局：这一行挂中间主顶栏，**不要**再在对话块叠第二行（D3 / D9 仍有效）。此时主顶栏是「对话标题栏 + 收紧文件列」，文件页签仍在右侧文件列自己的一行。

## §7 历史目录细则

抽屉宽、可拖、overlay 滚动仍按 06-方案 §9。本轮只在 portal **外壳**上加头，列表本体仍 `SessionSidebar` 的 tree。

```text
┌─ 历史 240 ─────────────┐
│ 🔍 搜索对话…            │  32px，圆角输入，占满
│ 新对话            ⌃⌥N  │  32px 行按钮，左图标右提示
│ 今天                   │  11px 弱字分组头
│   ○ 标题               │  现有 SessionTreeItem，可保留未读/运行
│     副标题 / 相对时间    │
│   ⋯ More               │  与条目同高，muted
│ 昨天                   │
│   …                    │
└────────────────────────┘
```

- 搜索：只滤**当前项目**下已加载的会话标题 / 首条摘要，不打新 API。
- 空结果：工具栏仍在，列表区一句「无匹配」。
- 分组头不进点击选中；不是手风琴（不要点头收起整组，避免和 More 两套折叠打架）。
- `⋯ More`：展开该桶剩余根会话。已展开可改为「收起」，或保持展开到下次进页。推荐可收起，文案「收起」。
- 不把 Cursor 的「Reading tool output」做成第二行状态（我们没有同等稳定的流式短句）；现有相对时间 / 消息数可留作副标题。

左栏无门户时（手机或未挂宿主）：本轮**不**给左栏列表加这套头，避免两处皮肤。桌面历史只活在抽屉里。

## §8 视觉节奏（不协调怎么收）

目标不是换肤，是 **三条轨同一密度**：

1. **高度**：文件顶栏 / 对话顶栏 / 历史工具行都是 32–36px，图标钮 32px，描边同一套 `--border`。
2. **字重**：标题 12px regular；分组头 11px `--text-muted`；菜单 12px。禁止再出现「会话」这种 11px 假页签字。
3. **主操作只有一种**：加号方钮，不用再写「新对话」在对话顶栏（对话顶栏靠标题承担语义；历史里才用整行「新对话」，因为那里没有会话标题）。
4. **对齐**：对话标题左内边距 12px，与历史搜索框左内边距对齐，两栏顶看起来像一副。
5. **细栏不是第二标题**：路径 11px、`--text-muted`、一行截断；页签继续承担文件名主识别。长路径**优先保住尾段**（`…/01-Projects/R…/00-README.md`），完整路径放 `title`。

## §8.1 细栏路径（修订 06-方案 §5）

PR-08 把「来源 / 视图 / 语言」放左侧，是为了填空、避免再写文件名。落地后这三词变成噪声：

| 现在细栏左 | 为何多余 | 改后 |
|------------|----------|------|
| 磁盘文件 / 生成 | 普通打开几乎恒为磁盘；绿点已表达「活文件」 | 不写。仅虚拟文档在路径后跟弱化「生成」 |
| 预览 / 原文档 / 对比 | 右侧 Source / Preview / Diff 已经是状态 | 不写 |
| markdown / html / png | 页签文件名自带后缀 | 不写 |

```text
[ docs/01-Projects/R20260819-03/00-README.md    ][ ● ][ Source | Preview ][ @ ][ ↓ ]
```

细则：

- 文案用 `getStatusBarFilePath`：磁盘绝对路径，虚拟 URI 原样。`@` 提及仍用相对路径。
- 所有 `FileViewer` 子视图（文本 / Markdown / 图片 / 其它已接细栏的）共用同一规则，避免一种文件写路径、另一种仍写「磁盘文件」。
- 截断：`text-overflow: ellipsis`，必要时 `direction: rtl` + 路径 `ltr` 嵌套，保证尾段（文件名 + 近父级）可见。
- 不在本轮做点击复制路径、面包屑分段跳转。
- **不恢复**已删的 36px 路径 title 行，也不把体积/行数重新做成主信息。

这是对 06-方案 §5「细栏左侧放原文档/来源/语言、不写文件名 title」的**定向修订**：不写 title，改写路径。
