## §1 方案概述

先把壳拆成三块**可换槽的组件**，再赋默认位置：

| 块 | 内容 | 编辑器布局（默认） | 助手布局（设置切换） |
|----|------|--------------------|----------------------|
| 导航块 | 项目名 + 目录树 + 底栏设置 | 左 | 左（不变） |
| 文件块 | 标签页 + 文件审阅 | **中** | 右（可收起） |
| 对话块 | 新对话 + 历史 + 过程 + 输入 | **右** | **中** |

```text
编辑器（默认，对齐 Cursor 编辑器窗口）
┌──────────┬────────────────────┬──────────────────┐
│ 目录树   │  文件 / 审阅        │  + 新对话 / 历史 │
│          │                    │  过程 + 输入     │
└──────────┴────────────────────┴──────────────────┘

助手（给「想在中间打字」的人）
┌──────────┬────────────────────┬──────────────────┐
│ 目录树   │  + 新对话 / 历史    │  文件 / 审阅     │
│          │  过程 + 输入       │  （可收起）      │
└──────────┴────────────────────┴──────────────────┘
```

不引入 Cursor Glass、底栏、双窗口。pi 独有能力仍降噪到对话块 `⋯` 或设置高级。

历史**永远跟着对话块走**，不在两种模式里各写一套左栏会话树。这是控制代价的硬约束。

## §2 双布局论证（回应增量诉求）

上一版把「设置里切换两套 UI」整档否掉，理由是过度设计。你补充后，需求变成：**默认服务你，同时兼容中间输入的人**。这不是自我否定，是范围扩大。要拆开三档看代价，不能用一句「兼容」或「不做」打发。

### 2.1 你不是「错误用户」

- 编辑器布局：文档是主舞台，对话是副驾驶——IDE 习惯。
- 助手布局：对话是主舞台，文件是产物——ChatGPT / 现网 pi-web 亲戚。

两种都成立。出厂默认跟发起人（编辑器）；另一种用设置给出来。Jakob 定律两边都照顾：人只学自己打开的那一套。

### 2.2 为什么推荐 B、不推荐 C

| 路线 | 内容 | 代价 | 结论 |
|------|------|------|------|
| A | 只做编辑器，不许切换 | 最低 | 满足你，挡掉中间输入人群 |
| **B** | 对话块、文件块整块对调；设置一项；`localStorage` 记住 | 在 A 的壳改上大约 **+30%～50%**。要把 `panel-layout.ts` 里写死的「chat 最小宽 / right=文件」改成「主栏 / 辅栏」。CSS 类名从 `file-panel` 中性化。测试多一种桌面排列 | **性价比最好** |
| C | 助手模式再把历史搬回左栏，编辑器模式历史在右；新建、空态、快捷键双份 | 约 **+1.5～2 工作包**，之后每个侧栏功能测两遍。`SessionSidebar` 拆不干净 | **本 R 代价过大，不做** |

C 才是「同时兼容两种产品」。B 是「同时兼容两种看文件/说话的位置」。  
对「我只想在中间打字」：B 够用。  
对「历史必须像 ChatGPT 钉在最左边」：B **达不到**——要在确认里写明，避免超卖。

### 2.3 实现要点（B 档，避免做成两套 App）

1. 抽出 `NavPanel` / `FileWorkspace` / `AgentPanel`（或等价组合），`AppShell` 只负责按 `layoutMode` 排槽。
2. `layoutMode`: `"editor" | "assistant"`，设置 → 外观与布局；键如 `pi-layout-mode`；禁止只存在内存。
3. 宽度记忆：编辑器下「右=对话宽」、助手下「右=文件宽」分键存储，避免来回切把某一栏撑爆。
4. 手机不提供该开关（继续抽屉）。
5. 切换即时生效，不刷新会话、不丢未发送草稿。

## §3 各栏怎么改（相对现状）

下列按**编辑器布局**写「搬走」；助手布局只是同一对话块出现在中槽。

### 3.1 左栏 · 项目与目录（两种模式相同）

**留下**

- 项目选择（展示名：文件夹名；悬停才出完整路径）
- 文件树（主体，占满剩余高度）
- 底栏设置齿轮

**搬走**

- 会话树 → **对话块**（不再因模式改回左栏）
- 「新建会话」主按钮 → 对话块顶
- 手动刷新会话 → 删除或设置高级
- worktree 切换 → 设置 · 高级 / 项目

**新行为**

- 默认过滤：点文件、`.git`、`node_modules`、`.next`、常见构建目录。
- 设置项：`显示隐藏文件` / `显示忽略的文件夹`。

### 3.2 文件块

- 现 `right-panel` 的 `TabBar` + `FileViewer` 成为独立块。
- 打开文件、对话内链接一律进文件块（编辑器=中，助手=右）。
- 顶栏只留属于「当前主工作区」的少量控件：折左栏、折辅栏。

空态（@待确认-2）只约束**编辑器布局**的中槽。助手布局下中槽是对话，无文件时右槽收起即可——这是助手模式的自然态，不再单独做成「对话吞掉中+右」。

### 3.3 对话块（历史 + 过程，整块搬家）

1. 顶条：`+` 新对话、可选搜索、`⋯`。
2. 历史：当前项目会话列表（从左侧搬来）。
3. 线程：`ChatWindow`。
4. 底：`ChatInput`（R01，本 R 不重做）。

新建对话使用当前左栏项目；无项目时 `+` 引导先选项目。

## §4 设置怎么分层

| 分栏 | 大众默认能看见 | 说明 |
|------|----------------|------|
| 外观与布局 | 主题、语言、完成提示音；**工作区布局：编辑器 / 助手**；显示隐藏文件 | 两个名字，不要第三种 Glass |
| 模型 | 已有 | 不动 |
| 技能 | 已有 | 不动 |
| 高级 | 插件、用量、系统提示、会话文件/id、Git/worktree、手动刷新 | 功能仍透明 |

主界面 token 气泡默认去掉；用量进高级。

### @待确认-4 · 双布局做到哪一档（本次主问）

- **A**：只要编辑器骨架，设置里不出现第二种。代价最低；中间输入的人只能忍。
- **B（推荐）**：设置切换编辑器 / 助手；对话块整体搬家；历史跟着对话。增量约半个工作包量级，可接受。助手模式**不会**把历史单独钉回最左边。
- **C**：再做成「助手=历史在左、对话在中」。更像 ChatGPT，但维护接近两套产品，**不建议本 R 做**。若你坚持 C，需要单独加一期，并接受后续每个侧栏改动双测。

### @待确认-1 · 左栏还要不要对话入口

- **A（推荐）**：左栏只留项目 + 目录。
- **B**：左栏再留「最近 5 条」。两种布局都会出现双入口，更乱。

### @待确认-2 · 编辑器布局下，一个文件都没开时中间显示什么

- **A（推荐）**：中间保持工作区空态；对话留在右（或助手模式下的对话槽，不跨槽吞栏）。
- **B**：无文件时临时让对话铺满中+右。省空间，但编辑器/助手切换时更跳。
