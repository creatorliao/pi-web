## 结论摘要

1. **输入框**：`composer-tokens` 已能同时识别多颗 `/skill:`，这只影响着色，不改发给 pi 的原文。
2. **已发送气泡**：只有「整段是 SDK 展开信封」时才画一颗可下拉芯片；第二颗被当成第一颗的参数纯文本。
3. **智能体**：`pi-coding-agent` 的 `_expandSkillCommand` **只处理行首第一颗** `/skill:name`，其后全部当 `args`。第二颗的 `SKILL.md` **不会注入**。若该技能开了 `disable-model-invocation`，模型几乎只能看到命令名，不能按技能正文运作。

## 当前进展

- 路线 C 已落地：`lib/skill-expand.ts` 发送前多展开；`slash-display` 解析多信封；气泡多芯片；侧栏 `/skill:A +N`。
- 单测：`skill-expand` / `slash-display` 已过。

## 当前 Gate

手验：同一条消息发两颗休眠技能，气泡两颗可下拉；session jsonl 里应有两份 `<skill>` 信封。
