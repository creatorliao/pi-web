## 目标（Why + What）

- **业务目标**：Pi Web 的字读起来像本机 IDE，不像网页把窄等宽字硬画在 11px 上。
- **用户价值**：路径、侧栏、对话铬条不刺、不糊、不「锯齿」；中文和西文重量接近。
- **成功标准**：
  1. UI 正文使用系统无衬线（Windows 上即 Segoe UI 一类），不拿 Web 等宽字体当界面字。
  2. 真正的代码 / 路径使用本机 IDE 默认等宽栈（Windows：Consolas），并限制最小字号，避免 11px Noto 发虚。
  3. 启动后不出现「先系统回退、再换成 Noto」的字重跳变（与 R-01 首屏稳定一起验收）。
  4. 深浅色下抗锯齿策略一致，不靠用户装 JetBrains Mono 才好看。

## 用户原话

字体有些地方不合适，感觉有锯齿，不愉悦；请对照 VS Code 或其他编辑器的默认字体。

## 功能需求（In Scope）

| # | 需求描述 | 优先级 | 来源 |
|---|----------|--------|------|
| F-01 | 分层字栈：`--font-ui`（界面）与 `--font-mono`（代码/路径）分开，禁止界面控件误用等宽 | 必做 | 用户观感 |
| F-02 | UI 默认对齐 VS Code workbench：Windows `Segoe UI`，macOS 系统西文，中文走系统黑体 | 必做 | 对照 IDE |
| F-03 | 等宽默认对齐 VS Code editor：Windows `Consolas, 'Courier New', monospace`；Mac `Menlo, Monaco, 'Courier New'` | 必做 | 对照 IDE |
| F-04 | 等宽用于：代码块、会话文件内容、输入框代码、路径副文。项目名、按钮、标题走 UI 字 | 必做 | 分析 |
| F-05 | 等宽字号桌面不小于 12px；11px 路径改为 12px 或改 UI 字 + tabular | 必做 | 锯齿主因 |
| F-06 | 去掉或降级 `next/font` 的 Noto Sans Mono 作为全局等宽（`display: swap` 造成跳变） | 应做 | 分析 |
| F-07 | Windows 渲染：`text-rendering` / 灰度抗锯齿与 VS Code 接近，不强制 `-webkit-font-smoothing: antialiased` 套在 11px 等宽上 | 应做 | Win10 截图环境 |

## 非目标

- 不引入必须联网下载的展示字体作为唯一方案（可作确认后的加分项）。
- 不改 Markdown 排版结构、不高亮主题大改。
- 不做用户「设置里选字体」第一期。
- 不处理启动闸门与露底（R-01）。
