## 1. 结论先说

不愉悦主要不是「没选到某种网红编程字体」，而是 **三件事叠在一起**：

1. **路径和大量 chrome 用了 Web 等宽字体 `Noto Sans Mono`，字号常年 11px。** 这类几何等宽在 Windows DirectWrite 小字号上容易显得细、硬、齿。
2. **`next/font` 的 `display: "swap"`**：先用回退等宽，下载后再换 Noto，启动阶段字宽和字重会跳——和 R-01 的「露底」叠在同一秒。
3. **界面字本身已接近系统栈**（`Segoe UI`），但被等宽路径条抢第一眼，人会把整栏都判成「锯齿字体」。

VS Code 的做法刚好相反：**界面用系统 UI 字，编辑器用本机默认等宽，不靠启动时换一张 Google 字体。**

## 2. 当前字栈

| 层 | 实现 | 问题 |
|----|------|------|
| UI | `html, body`：`-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`，14px | 方向对；Win 上就是 Segoe UI。中文回退到系统默认，未显式写「微软雅黑 / 宋体」 |
| 等宽变量 | `--font-mono: var(--font-noto-mono), JetBrains Mono, Fira Code, Consolas, …` | **Noto 排第一**。本机若没有 JetBrains/Fira，Consolas 永远轮不到 |
| Noto 来源 | `layout.tsx`：`Noto_Sans_Mono({ display: "swap" })` | 子集仅 `latin, cyrillic`，**不含汉字**。中文路径立刻掉到后面的雅黑/苹方，同一行西文 Noto、中文雅黑，字重和垂直对齐容易「一截一截」 |
| 使用面 | 侧栏路径、项目列表、大量设置与工具输出、`pre/code` | 选择器 11px 等宽长路径是截图里最扎眼的一块 |

`JetBrains Mono` / `Fira Code` 写在栈里但未打包、也未声明本机安装。对未装这些字体的 Windows 用户，它们是空名。

## 3. VS Code / Cursor 默认（对照用）

VS Code 源码 `src/vs/editor/common/config/fontInfo.ts`（社区长期引用的默认）：

| 平台 | 编辑器默认 `editor.fontFamily` |
|------|-------------------------------|
| Windows | `Consolas, 'Courier New', monospace` |
| macOS | `Menlo, Monaco, 'Courier New', monospace` |
| Linux | `'Droid Sans Mono', monospace`（发行版会再叠系统回退） |

字号默认：Windows / Linux 约 14，macOS 约 12。

Workbench（菜单、侧栏、标签，不是编辑器）：

| 平台 | UI 字 |
|------|--------|
| Windows | `Segoe WPC, Segoe UI, sans-serif` |
| macOS | 系统 `-apple-system` / SF 一类 |
| Linux | 发行版 UI 字 |

Cursor 桌面壳继承同一套 VS Code 默认；用户未改设置时，Windows 上仍是 **Segoe UI + Consolas**，不是 Noto，也不是 Inter。

本仓是 **浏览器里的 IDE 壳**，应对齐这套「系统 UI + 系统等宽」，而不是对齐「某篇落地页的几何 Grotesk」。

## 4. 锯齿从哪来（Windows 10）

| 机制 | 在本仓的表现 |
|------|----------------|
| 小字号几何等宽 | 11px Noto 的竖干只有 1 设备像素宽，ClearType 后仍像「刀口」 |
| 中西混排 | Noto 不含 CJK，路径 `D:\code\…` 还好；一旦有中文目录，一行两种字体 |
| font-display: swap | 回退 Consolas/系统 mono → 再换 Noto，轮廓从「软」变「硬」 |
| 可能的 `antialiased` | 若某控件将来套 `-webkit-font-smoothing: antialiased`，Win 上会把 Segoe 也画成偏细的灰度，和 VS Code 的 ClearType 不一致。当前 body 未强制这项，应保持 |

用户说的「锯齿」在浅色 11px 路径条上最容易成立；对话正文 14px Segoe 通常不是主嫌。

## 5. 差距

| 预期（IDE） | 现在 | 差距 |
|-------------|------|------|
| 侧栏标签是 UI 字 | 项目列表、路径是 11px Noto | 把导航当成代码 |
| 等宽 = Consolas（Win） | 等宽 = Noto（Web） | 和本机 VS Code 并排时违和 |
| 启动字族稳定 | swap 换字 | 和露底同一时段 |
| 中文路径一体 | 西文 Noto + 中文系统黑体 | 一行两种骨架 |

## 6. 依据

- `app/layout.tsx`：`Noto_Sans_Mono` + `display: "swap"`
- `app/globals.css`：`--font-mono` 栈与 `html, body` UI 栈
- `SessionSidebar` 路径 / 项目行：`fontFamily: var(--font-mono)`, `fontSize: 11`
- VS Code `DEFAULT_WINDOWS_FONT_FAMILY` / workbench `.windows { font-family: Segoe WPC, Segoe UI }`
