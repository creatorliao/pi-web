## 1. 目标与非目标

**做完之后**

- 界面字 = 系统 UI（Win 上结果为 Segoe UI + 微软雅黑；Mac 为 SF / 苹方）。
- 代码 / 需要对齐的 token = 本机 IDE 等宽（Win 上结果为 Consolas；Mac 为 Menlo）。
- 启动不再 `swap` 出 Noto；路径不再以 11px Web 等宽当主标签。
- 不依赖本机是否安装 JetBrains Mono / Fira Code。

**不做**

- 设置页选字体
- Inter / Geist / 新的 Google 字体
- Markdown 结构或高亮主题重做
- 启动闸门与露底（R-01）
- 为「更现代」改 Composer / 底栏槽位

## 2. 写入值（一次性改对）

### 2.1 `app/globals.css`

新增 `--font-ui`，重写 `--font-mono`，`html, body` 改走 UI 栈。

```css
:root {
  /* 系统字在前：Mac 用 SF/苹方；Win 上前两项不存在，结果仍是 Segoe + 雅黑 */
  --font-ui: -apple-system, BlinkMacSystemFont, "Segoe UI", "Segoe UI Variable",
    system-ui, "PingFang SC", "Microsoft YaHei UI", "Microsoft YaHei",
    sans-serif;
  /* 同上：Mac 用 Menlo；Win 上 Menlo/Monaco 通常没有，落到 Consolas */
  --font-mono: Menlo, Monaco, Consolas, "Cascadia Mono",
    "Droid Sans Mono", "Courier New", ui-monospace, monospace;
}

html, body {
  font-family: var(--font-ui);
  /* 其余 height / overflow 保持不动 */
}
```

说明：

- Linux 补 `Droid Sans Mono`（VS Code 编辑器默认），仍是系统回退，零下载。
- **不要**把 `JetBrains Mono` / `Fira Code` / `var(--font-noto-mono)` 写回 `--font-mono`。
- **不要**全局设置 `-webkit-font-smoothing: antialiased`。
- `pre, code` 继续 `font-family: var(--font-mono)`。
- 等宽最小 **12px**：凡 `fontFamily: var(--font-mono)` 且 `fontSize: 11`（或 CSS `11px`）的路径/代码，改为 `12`。纯 UI 标签可以维持 11，但必须是 `--font-ui`，不能继续套等宽 11。

### 2.2 `app/layout.tsx`

- 删除 `next/font/google` 的 `Noto_Sans_Mono` 整段。
- `<html>` 去掉 `notoSansMono.variable`。
- 主题脚本、PWA、`globals.css` 不动。

### 2.3 谁用 UI、谁用等宽

| 用 `--font-ui` | 用 `--font-mono`（≥12px） |
|----------------|---------------------------|
| 按钮、标题、欢迎标题、项目名、会话名、设置分栏名 | `pre` / `code` / Markdown 代码块 / Mermaid 源码 |
| 文件树**文件名**（对标 VS Code 资源管理器） | Composer 输入、代码 token、快捷键记号（Tab / Enter） |
| 对话正文（已是 14px 系统栈，改为显式 `--font-ui`） | 模型 id、header 名、路径**副文**、工具输出块 |
| 底栏项目名 | 底栏完整路径、git `+/-` 数字 |

路径：**不当左栏主标签**（R-01 D5）。本夹若 R-01 WP-B 尚未合入，过渡期左栏仍显示路径时也必须 12px，不得停留 11px Noto。

## 3. 控件审计（WP-T2 逐条改）

原则：标题/按钮上的 `fontFamily: var(--font-mono)` 改为 `var(--font-ui)` 或删掉（继承 body）；真正的路径/代码保留等宽并升到 ≥12。

### 3.1 必改（主嫌与决策对齐）

| 文件 | 现状 | 改成 |
|------|------|------|
| `app/layout.tsx` | Noto + `display: swap` | 整段删除 |
| `app/globals.css` `:root --font-mono` | Noto 第一、JetBrains/Fira 在 Consolas 前 | §2.1 栈 |
| `app/globals.css` `html, body` | 手写系统栈、无 `--font-ui` | `var(--font-ui)` |
| `components/SessionSidebar.tsx` 路径按钮约 1136–1155 | 11px mono 整段路径 | 项目名 UI（随 R-01 WP-B）；过渡则 12px。按钮脸禁止 11px mono |
| 同文件项目下拉约 1207 / 1244 | 11px mono 长路径 | 下拉删除后随 R-01；若暂留则 12px |
| `components/DirectoryPicker.tsx` 列表行 | 11px mono | 12px mono（这是路径浏览器，等宽合理） |
| `components/FileExplorer.tsx` 文件名约 142 | 11px mono | **UI 12px**；`+/-` 统计保持 mono，升 12 |
| `components/WorkspacePicker.tsx`（R-01 新建） | — | 标题 UI；副行路径 ≥12 |

### 3.2 升到 12、保持等宽（代码/路径/id）

下列保持 `--font-mono`，仅把 11（或 10）的等宽字号升到 **至少 12**：

| 文件 | 典型位置 |
|------|----------|
| `components/MessageView.tsx` | 工具名、工具路径、约 1002 / 1352 / 1451 的 11px mono |
| `components/ChatWindow.tsx` | `extensionRequest` 等 11px mono |
| `components/ChatInput.tsx` | 行号/快捷键旁 11px mono（约 1863）；菜单里的命令 token |
| `components/ContextUsageRing.tsx` | 11px mono 数字 |
| `components/FileViewer.tsx` | 约 83 的 11px mono |
| `components/ModelsConfig.tsx` | 模型 id `10px`/`11px` mono → 12；**输入框里的 id 保持等宽** |
| `components/AppStatusBar.tsx` | 路径类 mono |
| `app/globals.css` | `.extension-status-text` 等 `font-size: 11px` 且 `font-family: var(--font-mono)` → 12px |

设置/插件/技能里**作为代码或路径**的 mono 同样 ≥12；作为分类标题的改为 UI。

### 3.3 改回 UI 字（误把铬条当代码）

施工时在仓库搜 `fontFamily: "var(--font-mono)"` 与 `font-family: var(--font-mono)`，对每一处问：这是代码/路径/id 吗？

| 判断 | 处理 |
|------|------|
| 是代码、路径、模型 id、token 对齐 | 留 mono，字号 ≥12 |
| 是按钮标签、会话标题、分组名、说明句 | 改 `--font-ui` 或删除 fontFamily |
| 拿不准 | 对照 VS Code：侧栏用 UI，编辑器用等宽 |

已知偏铬条、应改 UI 的例子：`ChatInput` 里分组标题（若当前套了 mono）、`ModelsConfig` 供应商**显示名**（id 仍 mono）、`SessionSidebar` 会话标题行（若套了 mono）。

### 3.4 明确不动

- Markdown 正文字号/行高主题（`.markdown-body` 14 / 1.7 可留）
- KaTeX、Mermaid 渲染画布（源码 `<code>` 跟 `--font-mono` 即可）
- 高亮配色 class
- `ChatMinimap` 的几何（字族可继承；若 minimap 用 mono 显示代码预览则 ≥12）
