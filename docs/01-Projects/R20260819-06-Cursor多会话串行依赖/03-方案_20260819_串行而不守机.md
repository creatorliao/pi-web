# 方案：在官方能力上实现「串行、分上下文、不守机」

## 决策原则

按「完成条件长什么样」选路径，不要强行所有任务都开两个 IDE 聊天。

```text
完成条件能变成 Git/CI/Webhook？
  是 → 方案 L2（Automations 事件链）     ← 最不值守、上下文全新
  否，但是同一件大事的前后步？
        → 方案 L1（一计划 + 依赖步 / 父子 Agent）
  否，必须是两个对等任务且门闩是「A 的 Agent 跑完」？
        → 方案 L3（Cloud API 或 CLI 脚本 DAG）
```

---

## L1 · 官方 IDE 内：一个总控 + 隔离上下文（少脚本）

**何时用**：B 必须用 A 的结论，但你接受「总控还是一条会话」。

**做法**

1. 打开 **Agents Window**，先写计划：标出 B 依赖 A。
2. 用 **Build in Parallel** 只并行无依赖步；A→B 保持顺序。
3. 若 A、B 各自很长、怕污染上下文：总控只写门禁和验收，**子 Agent** 做 A，回来后再派子 Agent 做 B（每个子 Agent 独立 context）。
4. A 会跑很久：对 A 用 **`/in-cloud` 或交 Cloud**，你离开；回来看总控是否已收到结果再派 B。  
   - 注意：交云端不等于自动派 B，除非你接着用 L2/L3。

**In scope**：顺序、分上下文（子 Agent）、减少盯盘。  
**Out of scope**：两个对等侧栏聊天互相自动唤醒。

---

## L2 · 官方不值守：Automations 把「完成」变成事件（推荐默认）

**何时用**：A 的完成可以定义为 PR 合并、CI 绿、Linear 状态、或你方 Webhook。

**做法（示例：A 合入后才允许 B）**

1. 任务 A 用 Cloud Agent 或本机做完并开 PR（可 `/babysit` 看评）。
2. 新建 Automation：触发 = **PR merged**（或 **CI completed**），仓库对准本仓。
3. Prompt 写死任务 B（独立说明、独立验收）；运行环境是**新的** Cloud Agent → **新上下文**。
4. 需要第三段再挂「B 的 PR merged → C」。

**Webhook 变体**：A 的 CI 或本机 hook 在成功时 POST 到 Automation webhook，门闩不必是「合并」（例如「仅测试通过」）。

**In scope**：不同上下文、真串行、关电脑。  
**Out of scope**：纯本地、不上云、不把完成落到事件。

---

## L3 · 官方可编程面：Cloud API / CLI 自建队列

**何时用**：门闩就是「A 这次 run 结束」，且 B 必须是另一个 agent（新上下文）。

**做法**

1. 用 [Cloud Agent API](https://cursor.com/docs/cloud-agent/api/endpoints) 创建 agent A + 初始 run。
2. 轮询或 SSE，直到 run 结束（非 `CREATING`/`RUNNING`）。
3. **再** `create agent`（任务 B）——不要对 A `create run`，否则会共用 A 的对话状态。
4. 同一 agent 上若只是追问，利用官方「同时只能一个 run」即可，无需自建锁。

本地替代：`agent --worktree …` 跑完（进程退出）再起下一条 CLI；可用系统任务计划，无需开着 IDE UI。

**In scope**：硬串行、分上下文、可无人值守。  
**Out of scope**：官方图形化队列；要自己维护 agent id / 失败重试。

---

## 明确不推荐当「跨会话串行」的用法

| 做法 | 原因 |
|------|------|
| 两个侧栏聊天干等 | 没有官方门闩，只能人点 |
| 只靠 Worktree | 解决冲突，不解决启动顺序 |
| Hooks `stop` 里 followup 写「请去开另一个聊天」 | Agent 不能替你创建对等会话；只会污染本会话 |
| `/loop` 扫「另一个聊天好了没」 | 非官方跨会话产品；且另一聊天对你不可见 |

---

## 推荐组合（符合你的画像）

你是重度用户、常多开、要分上下文、讨厌守机：

1. **能事件化的依赖（合入、CI、工单状态）一律 L2** —— 这是官方最完整的「做完再开下一件、还是新 Agent」。
2. **还在同一功能里前后脚的**，用 L1，少开对等聊天。
3. **必须「A 的 Agent 停了才许 B」且 B 要全新对话**，上 L3；把 A/B 的 prompt 和完成定义写在本夹或仓库 `docs`，方便脚本引用。

本机多开聊天继续用于：**无依赖的并行**（配 Worktree），不要用来表达依赖。
