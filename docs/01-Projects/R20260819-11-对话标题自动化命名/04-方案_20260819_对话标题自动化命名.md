# 方案：对话标题默认自动命名（手工优先）

| 属性 | 值 |
|------|----|
| 日期 | 2026-08-19 |
| 状态 | Gate-S 已确认（2026-08-19）；默认值已按 §6 落地 |
| 依据 | [01-需求](./01-需求_20260819_对话标题自动化命名.md) · [02-分析](./02-分析报告_20260819_本仓标题命名源码.md) · [03-调查](./03-调查报告_20260819_同行标题命名做法.md) |

## 1. 产品判断

沿用现成 `generateSessionTitle` 与 `POST .../auto-name`，**补一门控和一次触发**。不重写生成器，不另建标题存储。

原则：

1. 没有持久化名称 → 机器可以写一次。
2. 有持久化名称 → 机器自动路径不写（无论这名字当初是人还是机器写的）。
3. 人随时可以 PATCH 覆盖机器。
4. 展示回退不是名称，不能挡住自动命名。

这避开 ChatGPT「后来又改用户标题」的坑，也避开 Open WebUI「解析失败却假装成功」的坑。

---

## 2. 推荐规格（默认选项）

### 2.1 何时自动跑

在**当前会话**出现「本轮已结束、会话已落盘、仍无 `session.name`」时触发一次：

- 信号对齐现有闲置语义：优先 `prompt_done`；若只有扩展注入、没有 wrapper 级 `prompt_done`，用已有的 `agent_settled`（与 `useAgentSession` 注释一致）。
- 不在用户按下发送时并行（不做 LibreChat `immediate`）。本仓工具调用多，生成器已经 `waitForIdle` + sanitize，final 更省事、更少 400。
- transient：不调 auto-name（与按钮一致）。等 hydrate 落盘后再由下一次 settled 补一次。
- 同一 `sessionId` 用 in-flight 锁；`naming` 期间不重入。

### 2.2 门控（必须同时满足）

| 条件 | 不满足则 |
|------|----------|
| `selectedSession` 存在且非 transient | 跳过 |
| 有可命名内容（与按钮相同：`userMessages` 或 `messageCount`） | 跳过 |
| **持久化 `name` 为空**（`!session.name?.trim()`） | 跳过 |
| 该 id 未在本次生命周期自动成功过（客户端 Set，防 settled 连打） | 跳过 |
| 未在 naming | 跳过 |

「用户手工命名」的判定：**文件里已经有非空 `name`**。侧栏未改动提交不会写盘，因此不会误伤自动。

用户若在自动返回前先改了名：写入前再读一次 `name`，或 PATCH 成功后把该 id 标为「勿覆盖」。推荐服务端在 `setSessionName` 前再看 `getSessionName()`，非空则 200 且不改，返回现名。避免竞态覆盖。

### 2.3 按钮怎么处理

**保留「生成标题」。** 用途改为：对已有自动名不满意时重来。  
行为建议（待确认）：

- **自动路径**：只填空名。
- **按钮路径**：允许覆盖自动名；若以后有 `titleSource=user`，按钮可先确认或直接覆盖（一期无来源字段时，按钮 = 用户显式要求，允许覆盖）。

### 2.4 写什么、失败怎么办

- 成功：现有 `setSessionName` + 刷列表 + 更新 `selectedSession.name` / `sessionStats.sessionName`。
- 失败：不写 `session_info`；展示继续回退；自动路径不强制红字（可 console / 弱提示）。按钮路径保持现有 error 态。
- 不要把 `firstMessage.slice(0,50)` 写进 `session_info` 冒充生成成功。

### 2.5 来源标记（推荐，小改）

在方案确认后施工时二选一：

| 选项 | 做法 | 利弊 |
|------|------|------|
| **A（推荐）** | `session_info` 增加可选 `source: "user" \| "auto"`（SDK 若不能扩字段，则本仓旁路：仅客户端 localStorage 记「用户锁」不可靠） | 真正分得清；依赖 SDK 是否透传未知字段 |
| **B（一期最小）** | 不加字段；「有 name 就停自动」 | 实现短；按钮重生成会变成「有名」，之后自动不会再跑，符合 F-02/F-03 |

一期若 SDK 不能稳妥存 `source`，用 **B**，仍满足用户陈述。A 放到发现 `session_info` 可带额外字段之后。

`@待确认`：选 A 还是 B。推荐 **B 先落地**，A 为增强。

## 3. 实现落点（确认后才改）

| 位置 | 改什么 |
|------|--------|
| `AppShell.tsx` | `handleAgentEnd` / settled 回调里调与 `handleAutoName` 相同的请求，加上 §2.2 门控；抽出 `requestSessionTitle({ force })` |
| `useAgentSession.ts` | 若 settled 只在 hook 内可靠，从这里通知壳层「可以尝试命名」，避免漏扩展注入轮次 |
| `auto-name/route.ts` | 增加 `force?: boolean`；`force !== true` 且 `getSessionName()` 非空则不覆盖 |
| 测试 | 门控：有名不请求；空名在 settled 后请求；transient 不请求；force 覆盖。现有 session-title 单测不动 |

不改 `TITLE_PROMPT`、不改解析、不改 shadow tools——02 证明这块已经够用。

---

## 4. 价值观核对

| 条 | 本方案 |
|----|--------|
| 默认可用 | 不用找按钮 |
| 用户意图优先 | 已有名不自动改 |
| 少制造状态 | 一次写入，不循环改名 |
| 失败可理解 | 仍显示首条截断，不当成功 |
| 不扩 scope | 顶栏点击改名、Task Model、表情标题都不做 |

## 5. 验收（确认施工后用）

自动（L2 可脚本锁门控，L3 手验一轮真模型）：

- [ ] 新会话发一轮，落盘后列表/顶栏变为模型标题，未点按钮
- [ ] 同一会话再聊一轮，标题不变
- [ ] 先侧栏改名再发消息，标题保持用户文案
- [ ] 先发消息自动命名，再侧栏改名，之后不再被改回
- [ ] 空会话 / transient 不打 auto-name
- [ ] 生成失败后仍显示首条截断，JSONL 无新 `session_info`
- [ ] 按钮仍能重生成（若 Gate-S 同意 force）
