## 结论先行

本仓**已经有完整的 LLM 标题生成器**，但只挂在按钮上，不是默认行为。侧栏和顶栏在「没有持久化名称」时用首条用户消息截断顶一下，看起来像有标题，其实文件里常常没有 `session_info`。用户手工改名走 PATCH，自动生成走另一条 POST，两者都会写成同一种「已有 name」，**没有「谁起的名」标记**。要做「默认自动、手工优先」，缺的是时机与门控，不是从零造生成器。

## 1. 用户能看见的三层名字

| 层 | 是什么 | 算不算「已命名」 |
|----|--------|------------------|
| 持久化名 | JSONL 里 `session_info.name`，经 `SessionManager.getSessionName()` / `setSessionName` / `appendSessionInfo` | 是 |
| 展示回退 | `session.name \|\| firstMessage 截 50 字 \|\| id 前 12` | 否 |
| 顶栏回退 | `name \|\| skill 折叠后的首条 \|\| 首条原文 \|\| 「新对话」` | 否 |

侧栏把 skill 展开块折回 `/skill:name args` 再截断，避免列表里出现大段 XML。重命名输入框用同一套回退文案预填；若用户没改就提交，**故意不写盘**，避免把回退文案误存成正式名。

来源：

- `components/SessionSidebar.tsx`：`title` / `commitRename`
- `components/AppShell.tsx`：`chatHeaderTitleFull`
- `lib/types.ts`：`SessionInfo.name?`

## 2. 功能地图

### 2.1 手工命名

| 项 | 事实 |
|----|------|
| 入口 | 侧栏行内重命名（悬停铅笔、Enter / blur 提交） |
| API | `PATCH /api/sessions/[id]`，body `{ name }` |
| 写入 | `SessionManager.appendSessionInfo(name.trim())` |
| 空名 | 服务端拒绝非 string；trim 后空串仍会写入（客户端一般 trim 后若与展示 title 相同则提前 return） |
| RPC | `set_session_name` → `inner.setSessionName`，同步清列表缓存 |

### 2.2 自动命名（现为手动触发）

| 项 | 事实 |
|----|------|
| 入口 | 顶栏「生成标题」按钮；移动端更多菜单同一动作 |
| API | `POST /api/sessions/[id]/auto-name` |
| 前置 | 有选中会话、非 transient、有消息（`userMessages > 0` 或 `messageCount > 0`）、当前不在 `naming` |
| 写入 | 活着的 AgentSession 上 `setSessionName(result.title)` |
| 反馈 | `naming` / `success` 1.8s / `error` 5s 后回 idle；切会话清状态 |

**全仓没有任何 `prompt_done` / `agent_end` 后自动调用。** `handleAutoName` 只出现在按钮 `onClick` 和菜单 `onSelect`。

### 2.3 生成器本身（可复用资产）

`lib/session-title.ts` 的 `generateSessionTitle`：

1. `sourceAgent.waitForIdle()`，避免主回复没写完就去要标题。
2. `sanitizeTitleMessages`：丢掉没有配对 `toolResult` 的 `toolCall`，避免提供商拒收残缺 tool 序列。
3. 至少要有一条 `user` 或 `compactionSummary`，否则报「没有可命名的用户消息」。
4. 克隆一份临时 `Agent`：同一套 systemPrompt / model / thinking / convertToLlm / streamFn；工具 `execute` 全部改成抛错（shadow tools），命名过程不能改仓库。
5. 若历史最后一条是 user：把 `TITLE_PROMPT` 拼进该条再 `continue()`，避免连续两条 user。否则另发一轮 `prompt(TITLE_PROMPT)`。
6. 超时 90s，超时 `abort`。
7. 从临时 Agent **新增**的 assistant 文本里解析标题。

提示词要求：跟用户主语言；写目标或结果，不写「聊天」本身；西文 4–12 词或 CJK 约 8–24 字；不调工具；只回纯文本。

`parseGeneratedSessionTitle`：拆代码围栏、抽 JSON 的 `title`、去掉「标题：」前缀、剥引号、只取首行、去末尾句号、无字母数字则失败、最长 80 字符。

测试覆盖：包装清洗、尾部 user 折叠、等主回复完成、压缩摘要可命名、shadow 工具不可执行、残缺 toolCall 剔除。`AppShell.auto-name.test.mjs` 只锁按钮禁用条件（压缩后仍可点、transient 不可点）。

### 2.4 路由与会话生命周期

`app/api/sessions/[id]/auto-name/route.ts`：

1. 解析会话文件；没有则 404。
2. 已有活着的 RPC wrapper 就复用，否则 `startRpcSession`（会真的拉起进程内 AgentSession）。
3. `waitUntilReady` 后生成标题。
4. 若生成期间 wrapper 被销毁 → 409。
5. `setSessionName` + `invalidateSessionListCache`。

代价：冷会话点一次生成标题，会把该会话载入 `__piSessions`（10 分钟空闲回收）。默认自动若发生在「刚聊完」则 wrapper 通常已在，成本主要是多一次模型调用。

## 3. 特性清单（现状）

| 特性 | 有无 | 说明 |
|------|------|------|
| LLM 摘要标题 | 有 | 同会话模型，全历史（清洗后） |
| 默认自动 | **无** | 必须点按钮 |
| 手工优先门控 | **无** | 按钮对已有 `name` 也会再生成并覆盖 |

| 展示回退 | 有 | 首条 50 字 / skill 折叠 |

| 压缩后仍可生成 | 有 | 摘要角色 + messageCount |
| 工具不可执行 | 有 | shadow tools |
| 超时 / 解析容错 | 有 | 90s；JSON / 纯文本 |
| 廉价任务模型 | 无 | 与主对话同模型、同 thinking |
| 进行中会话命名 | 部分 | 会 waitForIdle；按钮不禁止 streaming，但会等到闲 |

## 4. 与需求的缺口

| 需求 | 现状 | 缺口 |
|------|------|------|
| 默认自动、不用点 | 仅按钮 | 缺触发器（建议挂在首轮结束后） |
| 没名字才自动 | 展示回退常让人以为有名字 | 必须以「持久化 `name` 为空」判断 |
| 手工优先 | 生成按钮会覆盖已有名 | 自动路径必须 `if (name) return`；按钮是否仍允许覆盖见 01 待决 |
| 可追溯谁起的名 | 无 | 若只写 `name`，写过自动名之后无法再识别「这是机器写的」 |

手工命名的优先级，在数据上只能看「`name` 是否已存在」。因此：**自动命名一旦成功写入，之后的自动逻辑应停**；用户再 PATCH 只是改同一个字段。若希望「自动名可以刷新、用户名绝不刷新」，必须加来源标记（方案里推荐）。

## 5. 关键路径（便于施工时对文件）

```text
展示：SessionSidebar.title / AppShell.chatHeaderTitleFull
手工：SessionSidebar.commitRename → PATCH route → appendSessionInfo
按钮：AppShell.handleAutoName → POST auto-name → generateSessionTitle → setSessionName
生成：lib/session-title.ts（Agent 影子会话）
列表名：session-reader loadAllSessions ← SDK SessionManager.listAll().name
```
